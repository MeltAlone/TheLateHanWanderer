# ADR-0003：使用 C# / .NET 10 构建模拟核心

- 状态：已接受
- 日期：2026-07-24

## 背景

首个场景和行为验收已经明确：引擎需要强类型领域模型、稳定整数数值、事件驱动调度、长期事件日志、确定性回放、存档迁移和分层模拟。四日 Demo 很小，但正式世界预期包含数万具名人物、数千地点和百万级累计事件，因此技术栈不能只按命令行开发速度选择。

主要候选包括 Python、TypeScript/Node.js、Rust 和 C#/.NET。Python 与 TypeScript 适合快速内容工具和界面，但在大型常驻状态、长期类型契约和性能预算上需要更早引入额外约束；Rust 提供最高的控制力，但会显著提高首阶段领域模型变动和内容工具开发成本。

技术尖峰已经用实际 189 雒阳场景完成：JSON 加载与校验、规范化内容哈希、确定性最短路径、文书交付、承诺关闭、不可变事件、事件指纹、快照续跑、命令行适配器和 Release 构建。

## 决定

- 模拟核心使用 C# 和 .NET 10 LTS。
- 核心项目 `LateHan.Core` 不依赖 JSON、数据库、CLI、Unity、Godot 或其他表现框架。
- 场景、持久化和表现分别通过 `LateHan.Scenarios`、`LateHan.Persistence` 和 `LateHan.Cli` 适配核心。
- 规则时间、距离、资源、概率阈值和事件序号使用整数或显式定点数。
- 发布构建启用 nullable、确定性编译和警告即错误。
- 第一阶段不进入 Unity；未来图形客户端只能调用稳定应用端口和 DTO。
- SQLite 或其他数据库不是领域状态的所有者；事件和快照契约必须可在更换存储实现后继续使用。

## 理由

- C# 在强类型、运行性能、GC 工具、调试、测试和领域模型迭代速度之间平衡良好。
- .NET 自带高质量 JSON、加密哈希、集合和跨平台运行时，初始核心无需引入大量第三方依赖。
- 事件、快照和数据 DTO 可以显式版本化，不需要序列化运行时对象图。
- CLI、后台模拟、桌面客户端、Web 服务、Godot 和 Unity 都能以适配器方式接入同一核心。
- 技术尖峰在真实场景上达到 0 警告、测试确定性通过，并有足够性能余量继续实现事件调度器。

## 后果

- 开发环境需要与 `global.json` 匹配的 .NET 10 SDK。
- 内容作者仍可使用 PowerShell、Python 或其他工具，但最终场景验证规则应由 `LateHan.Scenarios` 提供权威实现。
- 必须主动控制对象数量、分配和事件日志驻留，不能因为托管运行时可用就忽略 LOD 和快照策略。
- 快照与事件契约需要显式迁移器；程序集内部类结构不是存档格式。
- 引入 Unity、ORM、消息总线或 Web 框架都需要保持依赖方向，不得反向渗入核心。

## 复审条件

满足任一条件时重新比较 Rust 或其他实现，而不是无条件迁移：

- B1 的 20,000 名 L2 人物和 200 万人口当量合成世界无法在 2 GiB 内运行；
- 30 日事件驱动模拟在优化数据布局后仍无法达到性能预算；
- 百万事件追加、快照恢复或因果查询出现运行时无法规避的瓶颈；
- 跨平台部署、AOT 或宿主引擎产生无法通过适配器隔离的约束；
- 实际团队的领域规则与内容迭代效率显著低于其他候选技术栈。
