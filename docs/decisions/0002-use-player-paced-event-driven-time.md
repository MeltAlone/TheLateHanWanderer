# ADR-0002：使用玩家定步的事件驱动世界时间

- 状态：已接受
- 日期：2026-07-24

## 背景

世界必须在玩家行动期间持续推进，但命令行和策略模拟需要给玩家充分思考时间。把“世界不停运行”直接实现为现实秒表，会让操作速度取代决策质量，也会使自动测试和确定性回放变得困难。

## 决定

- 玩家阅读状态和选择命令时，世界时间暂停。
- 玩家提交行动、等待或计划后，世界推进相应时长。
- 推进期间所有 NPC、消息、运输、组织计划和环境事件共享同一时间轴。
- 遇到允许玩家响应的中断时，时间停在中断发生的准确时点。
- 内部使用整数分钟作为公共时间分辨率，但系统通过事件调度运行，不进行全世界每分钟轮询。

## 理由

- 保留“天下不会等角色”的时间约束。
- 允许玩家认真阅读信息和推理因果。
- 天然适合命令行原型、自动模拟和分支比较。
- 相同命令序列和随机种子可以确定性回放。

## 后果

- 需要定义行动持续时间和可中断阶段。
- 同一时间戳上的冲突必须有稳定、非玩家优先的结算规则。
- UI 不可用现实动画时长暗中改变世界结果。
- 后续即使加入实时观看模式，也只能作为向事件时间自动提交“等待”的表现适配器。

## 复审条件

当首个可玩原型证明大量短行动导致操作过碎时，评估批量计划和日程托管，而不是优先改成现实时间制。
