# ADR-0001：分离史料主张、场景状态与模拟规则

- 状态：已接受
- 日期：2026-07-24

## 背景

历史模拟同时面对三类不同事实：史料声称发生过什么、游戏开局采用什么状态、引擎允许世界如何变化。如果混在同一份数据中，后续无法判断一个数值来自史书、设计推断还是模拟结果。

## 决定

采用三层边界：

1. `docs/research/` 与 `data/historical/` 保存带来源、时间范围和置信度的历史主张。
2. `data/scenarios/` 保存某次开局采用的完整世界状态，并明确引用历史主张与玩法假设。
3. `src/` 保存通用模拟规则，不硬编码特定历史人物、地点或预定结果。

场景生成过程必须可重复。历史资料发生修订时，应能明确识别受影响的场景字段。

## 理由

- 允许同一争议史实生成不同研究版本的场景。
- 防止“为了玩法填的数字”被后来误认为史实。
- 允许相同模拟内核运行不同日期、地区乃至不同历史时期。
- 便于测试规则错误、数据错误和史料错误分别属于哪一层。

## 后果

- 数据引用比直接填写 JSON 更繁琐。
- 需要来源 ID、主张 ID、转换记录和校验工具。
- 首个原型开始较慢，但后续迭代和纠错成本显著降低。

## 复审条件

当第一份机器可读场景生成后，检查三层边界是否导致无法接受的重复或性能成本。
