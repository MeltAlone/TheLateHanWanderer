# ADR-0006：以宏观个人生涯尺度重启正式游戏

## 状态

已接受，2026-07-25。

## 背景

分钟级洛阳技术原型已经验证事件调度、旅行、认知、承诺、因果、存档和规模能力，但实际试玩暴露了产品偏差：玩家看不见可去地点、需要输入内部 ID、中文交互不完整，玩法被单城分钟级送信牵制，无法形成《太阁立志传 V》式的三国个人生涯体验。

继续在旧核心上直接增加图形界面会把错误的时间尺度和交互模型固化进正式产品。完全建立新仓库又会丢失已有设计、研究、提交历史和可复用的验证成果。

## 决策

在同一 Git 仓库的 `game/` 目录建立正式游戏项目：

```text
LateHan.Game.Domain
  <- LateHan.Game.Simulation
  <- LateHan.Game.Content
  <- LateHan.Game.Persistence
  <- LateHan.Game.App
```

准确依赖为：

- `Domain` 不依赖界面、JSON、数据库或旧 `LateHan.Core`。
- `Simulation` 只依赖 `Domain`。
- `Content` 只依赖 `Domain`，负责场景组装。
- `Persistence` 依赖 `Domain` 和 `Simulation`，负责适配存档格式。
- `App` 位于组合根，可以引用以上项目并使用 Avalonia。
- 正式项目不得引用旧 `src/LateHan.Core`；需要的思想和规则按日/旬/月尺度重新实现。

玩家时间采用日、旬、月层级；空间采用战略地点与城内地点两层节点图；人物采用统一模型；玩家交互采用全中文可点击文本。Avalonia 是当前桌面表现层选择，不是领域架构依赖。

## 结果

正面结果：

- 正式产品不再被旧技术试验的分钟尺度绑架。
- 保留仓库历史和旧原型，方便对照已验证的因果与确定性语义。
- UI 可以快速验证可理解性，将来更换 Avalonia、增加网页或游戏引擎客户端时不重写领域层。
- 新领域模型可以围绕州郡旅行、身份、成长和关系自然扩展。

代价与风险：

- 一段时间内存在旧原型和正式项目两套模型，概念可能重复。
- 旧功能不能通过程序集引用直接复用，需要按新尺度逐项重建。
- 首个切片的 NPC 行为仍很浅，必须继续增加动机、认知和计划，才能兑现动态世界承诺。

## 被否决方案

- **继续扩展旧 CLI**：无法修正产品尺度，且玩家交互成本已经被试玩证伪。
- **给旧核心直接套 GUI**：界面改善不能解决分钟级、单城任务导向的问题。
- **新建独立仓库**：会割裂研究、架构决策和版本历史，没有带来相应收益。
- **立即使用 Unity 或 Godot**：当前瓶颈是世界规则与产品循环，不是渲染；引擎迁移不能替代领域建模。
