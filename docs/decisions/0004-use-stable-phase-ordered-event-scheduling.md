# ADR-0004：使用稳定的分阶段事件调度

> 状态：已接受<br>
> 日期：2026-07-24

## 背景

世界中的旅行完成、人物离开、物品转移、消息抵达和计划复评可能落在同一分钟。如果依赖集合遍历顺序、线程时序或“玩家优先”，同一存档会因运行环境或观察对象不同而产生不同结果。未来事件还必须跨存档保存，不能以委托或进程内对象引用表示。

## 决定

未来事件是 `WorldState` 的持久领域状态，使用稳定事件种类和结构化负载表示。队列严格按以下键升序结算：

```text
(due_minute, phase_priority, stable_subject_id ordinal, sequence)
```

阶段优先级固定为：

1. `death_or_removal`
2. `access_and_control_change`
3. `arrival_and_departure`
4. `delivery_and_transfer`
5. `perception_and_belief`
6. `plan_evaluation`
7. `summary_and_notification`

引擎先完成同一分钟的整个事件批次，再判断是否暂停给玩家。多个同刻中断不会使批次结算一半。队列事件发生后从待办队列移除，并成为不可变运行时事件；运行时事件保存其调度 ID、阶段和直接原因。

未来事件处理器若在结算中排定同一分钟的新事件，只能使用严格晚于当前键的阶段和主体顺序，否则必须延至下一分钟或被拒绝。取消能力加入后必须按稳定调度 ID 记录取消结果，不能依赖从堆中物理删除的偶然顺序。

开发者修改队列属于外部干预：必须产生 `debug_intervention` 事件，并将回放标记为 `modified`。

## 理由

- 排序键只由持久整数、枚举和稳定 ID 构成，独立于运行时实现。
- 阶段表达世界因果中的最小先后约束，同时避免为玩家设置隐藏优先权。
- 同刻整批结算使存档总能落在完整事件边界，也避免一个中断遮蔽同刻死亡或控制权变化。
- 可序列化事件种类允许 CLI、服务器和未来图形客户端共享同一核心。

## 后果

- 所有耗时行动最终都必须通过事件边界推进，不能直接把时钟跳到终点。
- 新事件阶段或阶段语义变化属于规则兼容性变更，需要迁移或新规则版本。
- 当前尖峰已让 `wait` 使用队列；移动、交付和陈述仍需改造成持久行动阶段，才支持行动中途保存与恢复。

## 复审条件

只有在固定阶段无法表达经测试确认的因果冲突，或大规模基准证明该排序结构无法满足预算时复审。性能优化不得改变可观察顺序。
