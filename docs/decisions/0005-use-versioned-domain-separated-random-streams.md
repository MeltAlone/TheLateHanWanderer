# ADR-0005：使用版本化、按领域隔离的确定性随机流

> 状态：已接受<br>
> 日期：2026-07-24

## 背景

动态历史模拟需要不确定性，但默认运行时随机数不保证跨版本序列稳定。若所有判定共用一个游标，增加天气、界面动画或无关人物就会改变董卓的决策和玩家旅途，导致存档无法续跑、问题无法重现。

## 决定

MVP 随机算法固定为 `xoshiro256ss.v1`。每条流保存四个 64 位无符号状态字和 64 位抽取次数；算术使用 C# 未检查的 `ulong` 回绕语义。算法用公开的 `[1,2,3,4]` 初态参考向量锁定。

流按 `domain:stable_entity_id` 命名。初始四状态字使用 `sha256-le.v1` 派生：

```text
UTF-8(
  rng_version + NUL +
  uppercase_16_digit_root_seed_hex + NUL +
  domain + NUL +
  stable_entity_id
)
-> SHA-256
-> 依次按 little-endian 读取四个 ulong
```

领域名和实体 ID 不得包含 NUL 或冒号。每条流首次实际抽取时才进入世界状态；只读开发者预览在流副本上运行，不创建流也不推进游标。根种子、派生版本、所有已创建流状态和抽取次数都写入快照。

## 理由

- `xoshiro256**` 实现小、整数语义明确，适合固定并自行测试，不依赖框架内部实现。
- SHA-256 派生使流创建顺序无关，并用领域和实体 ID 隔离系统变化。
- 保存完整状态而非只保存抽取次数，允许快速恢复且不需要重放全部历史。
- 显式字节序和规范化根种子避免不同平台各自解释种子。

## 后果

- 任何算法、派生材料、字节序或 ID 规范变化都必须使用新的 `rng_version` 或派生版本。
- 调用方必须选择稳定、语义明确的领域名，不能为临时循环序号创建永久流。
- UI 随机性不得调用模拟流；需要表现随机时应由客户端维护独立状态。
- 快照 schema `0.2` 以前没有随机流状态，不能由当前尖峰静默加载。

## 复审条件

只有在统计质量、并行分支能力或规模基准出现可复现问题时复审。替换算法必须提供迁移策略，不能让已有回放悄然改变。
