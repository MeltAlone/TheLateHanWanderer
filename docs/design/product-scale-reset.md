# 正式游戏产品尺度重置

> 状态：已接受
>
> 日期：2026-07-25
> 适用范围：`game/` 下的正式游戏实现

## 1. 正式产品定义

《汉末浮生》是一款以日、旬、月推进的三国个人生涯与动态历史模拟游戏。玩家在州郡和城邑之间旅行，以身份、能力、关系、财富和信息参与世界；人物与势力依据有限认知持续行动，玩家可以观察、利用或改变历史，但不是世界唯一的行动中心。

它借鉴《太阁立志传 V》的不是某套具体菜单，而是三个结构：个人身份进入大历史、地图与城市构成生活空间、世界在玩家行动之外继续变化。

## 2. 对旧方向的校正

原有 `src/` 与 `tests/` 证明了分钟调度、持久行动、有限认知、承诺、因果、存档和大规模归档可以实现。这些成果继续作为技术原型保留，但不再定义正式游戏的玩家尺度。

- 旧洛阳送信场景是规则集成试验，不是正式可玩 Demo。
- “个人视角”不等于“分钟级日常操作”。
- 正式游戏不引用旧 `LateHan.Core`；成熟思想按新尺度重新实现。
- 分钟只可用于未来少数特殊场景的内部结算，不出现在常规界面。
- 不继续扩展旧 CLI 的玩家命令；CLI 仍可服务诊断和回归测试。

## 3. 时间尺度

玩家看到并直接消费的最小常规时间单位是“日”。

| 层级 | 职责 | 典型变化 |
|---|---|---|
| 日 | 玩家行动和近身人物行动 | 旅行、拜访、训练、工作、打听消息 |
| 旬 | 地方世界结算 | 人物计划复评、物价和治安趋势、征发与流言扩散 |
| 月 | 中长期状态结算 | 俸禄、债务、组织目标、人口物资和势力战略 |
| 年/季节 | 历史环境 | 年龄、收成、气候、服役周期和大事件条件 |

一个按钮必须明确显示预计耗时。时间推进期间，所有相关人物和势力使用相同世界时钟，不给玩家隐藏暂停权。

## 4. 空间尺度

空间使用有层级的节点图，而不是连续自由移动。

```text
天下
  州 / 司隶
    郡国
      城邑、关隘、渡口（战略地图节点）
        官署、客舍、市、宅邸、学舍、军营（城内地点）
          在场人物、设施、可用行动
```

- 战略地点具有类型、所属区域、地图坐标、描述和道路连接。
- 道路保存端点、行程日数、路况语义和未来可扩展的风险。
- 城内地点从属于一座城邑，不与天下地图节点平铺。
- 人物必须处于某座战略地点的某个城内地点，才能被当面交互。
- 玩家永远通过中文名称、地图节点、人物卡片和上下文按钮操作，不输入内部 ID。

## 5. 人物尺度

所有具名人物使用统一根模型，不按“武将”“女性”“剧情人物”拆成能力不对等的类型。

基础字段包括：

- 姓名、字、性别、年龄与健康。
- 身份、职务、组织归属、社会标签和合法权限。
- 统率、武艺、智略、政务、交涉、学识六项通用能力。
- 性格、价值取向、欲望、恐惧、责任和短中期动机。
- 关系、名望、财富、持有物、承诺与社会债务。
- 当前地点、当前行动、有限认知和计划。

角色标签可以组合。例如一人可以同时是官员、将领和士人。女性角色与男性角色共享完整人物结构；历史处境通过身份、权限、家庭网络和社会规则表达，而不是删减人物能力。

## 6. 核心循环

```text
观察日期、地点、人物和消息
  -> 选择旅行、谋生、成长、交游或承诺
  -> 消耗数日并支付资源
  -> NPC 与势力同步行动
  -> 日/旬/月结算改变世界
  -> 玩家获得新的机会、限制和信息
  -> 再次选择
```

菜单不是固定剧本清单，而应逐步由世界状态生成：人物是否在场、玩家是否认识对方、身份是否准入、关系是否足够、持有什么、知道什么、答应过什么，都会决定可选行动。

## 7. 首个纵向切片

首个正式切片以 189 年京畿与中原为舞台，验证 60 至 90 日的个人生活与世界变化。

- 8 个战略地点：洛阳、孟津、河内、虎牢关、成皋、荥阳、陈留、颍川。
- 每个战略地点至少 3 个城内地点；首批共 24 名具名人物。
- 3 个开局身份：寒门士子、郡府小吏、游侠。
- 全中文、可点击的桌面界面，不要求立绘和动画。
- 可完成：选身份、看地图、跨城旅行、进城内地点、看人物、拜访、打听、训练、谋生、休整、存档和读档。
- 世界证据：NPC 在玩家休整或旅行期间迁移，跨旬产生世界结算日志。

当前切片不做战斗、军团战、全国地图、数百人物、复杂经济、官职树、婚姻和自然语言自由输入。这些是后续系统，不应阻塞方向验证。

## 8. 方向验收红线

后续每个阶段都必须满足以下条件：

1. 新功能首先增强个人生涯、地图世界、人物关系或动态历史，而不是增加微观操作负担。
2. 玩家常规行动以日计，旬和月承担世界结算。
3. 玩家界面没有内部 ID、英文命令或必须阅读开发文档才能发现的行动。
4. 世界变化不能全部等待玩家触发；至少能指出一项玩家之外的行动及其原因。
5. UI 只依赖应用服务和领域端口；更换 UI 技术不重写领域规则。
6. 历史数据区分史实、合理推断和玩法假设，不把不确定材料伪装成精确事实。
