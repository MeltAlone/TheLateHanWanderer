# 历史研究方法与数据规范

> - 状态：0.1 初稿
> - 目标：让每一个进入模拟的历史字段都可以回答“依据是什么、对应何时、可信到什么程度”。

## 1. 基本原则

1. **先确定时间，再讨论状态。** 同一人物一年内可能数次转任或迁移。
2. **先保存主张，再做裁决。** 史料冲突不能被数据库唯一键静默覆盖。
3. **来源可靠性与主张置信度分开。** 可靠史书中的某条传闻仍可能低置信。
4. **缺失不是零。** 未记载太守、人口或驻军，不代表该值不存在或为零。
5. **不制造假精确。** 史料只支持区间时，游戏不能伪造个位数库存。
6. **历史数据与玩法假设分开。** 所有补齐世界的假设必须能被单独替换。
7. **名称不是身份。** 同名人物、异名地点和历代同址异治所必须使用稳定 ID 区分。

## 2. 来源层级

来源层级用于安排查证顺序，不自动决定具体主张的真假。

| 层级 | 来源类型 | 用途 |
|---|---|---|
| P1 | 正史纪、传、志及早期注引材料 | 事件、官职、人物、制度和行政区划骨架 |
| P2 | 编年史、类书所存佚文、出土材料 | 补充日期、因果链和互证 |
| M1 | 现代点校、历史地图集、制度史、专题研究 | 文本校勘、空间对齐和解释争议 |
| M2 | 学术数据库、历史 GIS、人物数据库 | 实体对齐、坐标候选和检索 |
| L | 通俗读物、百科与游戏资料 | 只用于发现线索，不直接进入正式主张 |

## 3. 来源记录

每个来源使用稳定 ID，并记录：

```yaml
id: source.hhs.069.wikisource
work: 后汉书
section: 卷六十九·何进传
edition_or_host: 维基文库在线转录
source_level: P1-access-copy
url: https://...
accessed_at: 2026-07-24
verification_status: checked_online
limitations:
  - 方便检索，不替代中华书局点校本
```

同一作品的点校本和在线转录是两个来源记录，二者可以共同支持一条主张。

## 4. 历史主张

历史主张是“某来源在某一时间范围内对某主体作出的陈述”。推荐字段：

```yaml
id: claim.189.hejin.office.general_in_chief
subject: person.he_jin
predicate: holds_office
value: office.general_in_chief
valid_time:
  start: zhongping-1-03-wushen
  end: zhongping-6-08-wuchen
time_precision: day
source_ids:
  - source.hhs.008.wikisource
  - source.hhs.069.wikisource
confidence: A
status: asserted
notes: 八月戊辰被杀，终止时间可确定到日。
```

主张本身不等同于运行时真相。场景构建器会选择一条主张、一个区间内采样值，或一个明确的玩法假设，生成确定的初始状态。

## 5. 置信度

| 等级 | 含义 | 场景处理 |
|---|---|---|
| A | 多个高质量来源一致，或单一明确制度/日期记录 | 可直接采用，仍保留来源 |
| B | 可靠来源明确记载，但缺少独立互证或存在小范围校勘问题 | 默认采用，允许后续修订 |
| C | 来源冲突、时间或地点只能约束到范围 | 场景必须声明选择或采样规则 |
| D | 史料空白，仅能根据制度、环境或玩法推断 | 标记为 `inferred` 或 `gameplay_assumption` |

置信度评价的是“这条具体主张”，不是对整部史书打分。

## 6. 冲突处理

发现冲突时：

1. 为每个版本建立独立主张。
2. 检查是否只是历法、年龄算法、异名或时间粒度差异。
3. 记录各来源成书年代、材料来源和文本异同。
4. 在研究结论中给出当前采用方案和理由。
5. 场景数据引用采用方案，但不得删除未采用主张。

首批已发现示例：《后汉书·灵帝纪》载刘辩即位时“年十七”，《资治通鉴》载“年十四”。原型当前不需要以年龄驱动精细身体模型，因此先保留冲突，不擅自裁决。

## 7. 时间规范

### 7.1 历史时间

研究层优先保存原始纪年：年号、月、干支日和原文时间词。公历日期是派生字段，必须由至少两种可靠方法校验。

```yaml
historical_date:
  era: 中平
  year: 6
  lunar_month: 8
  day_ganzhi: 戊辰
gregorian_date: null
conversion_status: pending_double_check
```

“某月”“数日后”“俄而”等模糊表达必须保存为时间区间，不能强制落到一个精确时刻。

### 7.2 有效时间与记录时间

- `valid_time`：历史世界中该状态成立的时间。
- `recorded_time`：来源或研究记录形成的时间。

二者不能混淆。后世编纂的《资治通鉴》可以描述 189 年发生的事件，但其记录时间远晚于事件时间。

## 8. 空间规范

每个历史地点至少包含：

- 稳定地点 ID；
- 当时名称和异体字；
- 地点类型与行政隶属；
- 有效时间范围；
- 治所与辖境的区别；
- 古代文本给出的相对位置或里程；
- 现代坐标候选及其来源和误差半径。

“陈留郡”“陈留县”“陈留郡治”和现代开封陈留镇不是同一个数据对象。GIS 点只代表坐标候选，不能代替历史行政关系。

## 9. 数量与物质条件

人口、粮食、军队和价格必须记录测量时点与口径。

- 《郡国志》户口数据是较早时期的行政统计基线，不是 189 年实时人口。
- “数千”“数万”保存为模糊数量级，不强制转换为精确整数。
- 未知城市库存由场景生成规则估算，并标记为玩法推断。
- 环境事件只影响有证据支持的变量。连续降雨可以提高道路泥泞风险，但不能无证据直接推导全城饥荒。

## 10. 官职与控制权

官职主张至少区分：

- 正式任命；
- 实际到任；
- 法定辖区；
- 实际控制；
- 临时屯驻或奉命行动。

例如王允任河南尹，代表京畿地方行政身份；并不意味着他自动控制宫城禁军。桥瑁任东郡太守而奉召屯成皋，也不意味着他是成皋的地方长官。

## 11. 从研究到场景

每个场景字段必须具备下列来源之一：

```text
historical_claim       有来源的历史主张
bounded_inference      在历史约束内的推断
gameplay_assumption    为使世界闭合而加入的可替换假设
simulation_seed        由固定种子在允许范围内生成
```

场景构建报告应列出所有 `gameplay_assumption`，使设计者可以集中审查世界中“我们自己发明了什么”。

## 12. 审核流程

1. 建立来源记录。
2. 摘录最短必要原文和定位信息。
3. 建立原子化主张。
4. 查找至少一个互证或反证来源。
5. 评定置信度与时间、空间精度。
6. 由另一轮审查检查是否存在现代常识倒灌。
7. 进入机器可读数据。
8. 生成场景后运行约束检查。

## 13. 当前研究禁区

在完成专门研究前，不作以下断言：

- 189 年某城的精确人口、粮仓库存和市场价格；
- 任意两地按现代公路里程计算的汉代行程；
- 未被来源明确定位的人物在某一时辰的精确坐标；
- 地方官职必然带来对军队、城门或豪强的实际控制；
- 《三国演义》情节等同于历史事实。
