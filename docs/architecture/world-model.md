# 世界模型

> - 状态：0.1 概念模型
> - 目标：定义历史研究、场景构建和运行时模拟之间共享的语言与边界。
> - 非目标：当前不确定编程语言、数据库或序列化框架。

## 1. 核心命题

世界的最小运行单元是：

> 一个行动者基于有限认知，在具体时间与地点，以可承担的成本执行行动；行动产生事件，事件改变客观状态、传播信息并进入其他行动者的未来决策。

世界模型必须支持：

- 确定的运行时真相；
- 不确定且可能冲突的历史研究；
- 每个人物不同且可能错误的认知；
- 可追溯的状态变化；
- 相同输入得到相同结果的确定性回放。

## 2. 五种不能混淆的“事实”

| 类型 | 示例 | 所属层 |
|---|---|---|
| 历史主张 | 《后汉书》称王允任河南尹 | 研究层 |
| 场景采用值 | 本场景在丁卯辰时将王允置于河南尹官署 | 场景层 |
| 客观状态 | 当前世界时间 08:30，王允在官署 | 运行时真相层 |
| 人物信念 | 袁绍认为王允在何进府 | 认知层 |
| 叙事陈述 | 玩家听说王允正在调集吏员 | 表现层 |

玩家和 NPC 的行为只能读取其认知层允许的内容。开发者工具可以查看客观状态和完整因果。

## 3. 顶层对象

### 3.1 Entity（实体）

实体是具有稳定 ID、可被事件引用的对象：

- 人物
- 地点
- 组织
- 官职或角色
- 物品与物资批次
- 军队、商队、信使和其他移动群体
- 消息、文书、命令和承诺
- 历史或运行时事件

名称是实体的时态属性，不是 ID。`place.luoyang` 可以在不同时期拥有“雒阳”“洛阳”等显示名称。

### 3.2 Component（组件）

组件保存实体某方面的当前状态。首批组件包括：

- `Identity`
- `TemporalValidity`
- `Position`
- `Containment`
- `RouteConnections`
- `PhysicalCondition`
- `Capabilities`
- `PersonalityAndValues`
- `NeedsAndGoals`
- `Inventory`
- `OrganizationMembership`
- `OfficeAndAuthority`
- `Relationships`
- `Beliefs`
- `Memories`
- `ScheduleAndCommitments`

不采用一个包含所有字段的巨大人物类。组件边界允许普通人物、军队、信使和官署只拥有自己需要的状态。

### 3.3 Action（行动）

行动是行动者试图改变世界的过程，具有持续时间、成本、前置条件和中断点。

### 3.4 Event（事件）

事件是已经发生且不可变的记录。重大状态只能由事件投影产生或修改。

### 3.5 Claim（历史主张）

历史主张只存在于研究与场景构建阶段。运行时世界不能把两条互相冲突的历史主张同时当作客观真相。

## 4. 时间模型

### 4.1 内部时间

运行时使用从场景纪元起算的整数分钟：

```text
WorldInstant = Int64 minutes_since_scenario_epoch
```

这不表示所有系统每分钟轮询。分钟只是排序和持续时间的最小公共单位。

### 4.2 历法服务

历法服务负责：

- 汉代年号、月、干支日与内部时间互转；
- 日出、时辰和季节性时间显示；
- 保存尚未完成现代公历映射的场景；
- 阻止把未经校验的公历日期写回历史主张。

### 4.3 事件调度

系统维护按时间排序的事件与行动队列：

```text
玩家提交行动
→ 将行动的阶段和完成事件加入队列
→ 推进到下一个事件时间
→ 结算所有同刻事件和冲突
→ 如出现玩家可处理的中断则暂停
→ 否则继续推进到行动完成
```

决策界面暂停世界，但角色已经开始的行动不会因为玩家打开菜单而获得额外世界时间。

### 4.4 同刻排序

同一时间戳的事件不能简单按“玩家优先”。排序依据：

1. 已经开始的物理完成事件；
2. 强制中断与死亡、失能；
3. 同一资源的冲突仲裁；
4. 消息送达与认知更新；
5. 新决策调度。

具体优先级需在实现前建立 ADR，并用测试证明不会产生顺序漏洞。

## 5. 空间模型

### 5.1 地点层级

`Place` 同时支持包含关系和道路关系：

```text
行政包含：河南尹 → 雒阳县 → 雒阳城
物理包含：雒阳城 → 南宫 → 嘉德殿
道路连接：雒阳城门 ↔ 偃师 ↔ 巩 ↔ 成皋
```

行政隶属和物理可达性是两种关系，不能用一棵树同时代替。

### 5.2 Position

位置至少有三种精度：

- `exact`：在嘉德殿前。
- `contained`：在南宫内，具体房间未知。
- `range`：在成皋至雒阳的路段上。

场景可以用范围表达历史不确定性，但运行开始时必须由构建器选择确定位置或明确保留为“场外抽象群体”。角色自己的认知仍可保持模糊范围。

### 5.3 路线

路线是有方向的边，包含：

- 起点和终点；
- 距离及来源；
- 地形、路面和坡度；
- 通行方式；
- 门禁、关卡和渡河条件；
- 季节、天气和战争修正；
- 当前控制者与治安状态；
- 允许的吞吐量。

现代直线距离只可作为缺省估算输入，不能被标记为汉代道路里程。

### 5.4 进入权限

进入地点是一项行动，前置条件可以包括：

- 地点开放时间；
- 官职、身份和通行凭证；
- 守卫认知与关系；
- 容量、拥堵和警戒状态；
- 是否愿意违法、贿赂或强行进入。

“与某人在同城”不能跳过进入建筑、通报和等待过程。

## 6. 人物模型

### 6.1 稳定特征与动态状态

稳定或缓慢变化：

- 出身、亲族、教育背景；
- 性格倾向和价值观；
- 长期能力与身体基础；
- 长期抱负和身份认同。

快速变化：

- 位置、疲劳、饥饿、伤病；
- 当前情绪和压力；
- 短期目标和日程；
- 资产、消息和关系状态；
- 对风险和他人的即时判断。

### 6.2 能力

能力不压缩为五维武将属性。第一阶段按行动域建模：

- 识字与文书
- 行政与组织
- 交涉与察言
- 调查与隐蔽
- 商业与估价
- 骑乘与旅行
- 武器与徒手冲突
- 医疗与身体知识
- 军事组织与局部指挥

能力分为知识、训练和实际经验。知道兵法不等于能够稳定指挥陌生部队。

### 6.3 性格、价值观和动机

性格修改风险偏好和决策权重，不直接生成固定行为。动机来自：

- 生存和身体需求；
- 亲族与关系义务；
- 官职职责；
- 财富、名望和权力目标；
- 忠诚、名节、信仰等价值；
- 近期事件形成的恐惧、愤怒和复仇目标。

### 6.4 关系

关系为有方向、可不对称的多维边：

```yaml
from: person.a
to: person.b
trust: 0.7
affection: 0.2
respect: 0.8
fear: 0.4
resentment: 0.1
obligation: 0.6
interest_alignment: 0.5
evidence_events: [event.123, event.991]
```

关系变化必须引用事件。系统可以缓存数值，但必须能够追溯构成数值的主要经历。

### 6.5 记忆

记忆是人物对事件的主观记录，不是事件日志的复制：

- 人物可能没有见到完整事件；
- 人物会错误归因；
- 记忆强度随情绪、复述和时间变化；
- 后续证据可以修正人物的解释，但不必删除旧记忆。

## 7. 组织与权力模型

### 7.1 组织

组织由成员、角色、资产、规则、目标和内部关系组成。组织不会自己行动，具体人物或已授权的自动程序代表组织发起行动。

首批组织类型：

- 朝廷与官署；
- 宫廷与禁军单位；
- 大将军府和人物幕府；
- 郡县行政机构；
- 军队与临时营地；
- 宗族、商旅和居民群体。

### 7.2 官职与权限

官职定义法定能力：

```yaml
office: office.henan_intendant
jurisdiction: place.henan_intendancy
legal_powers:
  - investigate_local_officials
  - issue_local_administrative_orders
  - request_law_enforcement
appointment_authority: organization.imperial_court
```

实际执行还依赖：

- 是否到任并持有印信；
- 下属是否承认命令；
- 是否控制必要人员和物资；
- 命令能否及时送达；
- 其他权力系统是否阻止。

### 7.3 命令

命令是可移动的信息实体，包含签发者、授权依据、接收者、内容、期限、验证方式和传播载体。接收者可以服从、延迟、误解、质疑真伪、泄密或拒绝。

## 8. 资源与经济模型

### 8.1 资源批次

对会运输、损耗或追踪来源的物资使用批次：

```yaml
resource_batch:
  type: grain
  quantity: 120
  unit: shi
  owner: organization.example
  location: place.warehouse.example
  quality: 0.86
  provenance: event.harvest_or_purchase
```

钱币等高频可互换资源可以聚合，但跨地点转移仍必须通过行动或运输事件。

### 8.2 人口

重点人物使用独立实体。普通人口使用群体实体：

- 人数区间或场景确定值；
- 户籍、职业和依附关系；
- 健康、财富和态度分布；
- 所在地点与迁移倾向。

当普通人物进入关键关系或长期因果链时，可从群体中提升为具名实体，并从群体数量中扣除。

### 8.3 市场

市场是交易场所和撮合规则，不是无限库存商店。价格来自：

- 实际可售库存；
- 当前和预期需求；
- 运输与风险成本；
- 参与者掌握的信息；
- 法令、征发和囤积行为。

第一版无需模拟每笔小额消费，但所有影响组织计划和玩家选择的大宗交易必须进入事件日志。

## 9. 信息与认知模型

### 9.1 客观命题与人物信念

运行时客观状态可以投影为命题，例如：

```text
position(person.dong_zhuo) = place.sunset_pavilion
```

人物信念保存：

```yaml
proposition: position(person.dong_zhuo)
believed_value: place.mianchi
confidence: 0.65
learned_at: world-minute-120
source: person.merchant_17
evidence_messages: [message.88]
```

人物决策使用 `believed_value`，而不是客观状态。

### 9.2 消息

消息是对一个或多个命题的表达：

- 原始内容；
- 发送者和载体；
- 产生时间；
- 传播链；
- 每次转述产生的变形；
- 接收者对来源的信任；
- 是否加密、盖印或需要身份验证。

### 9.3 观察

观察是行动。结果受距离、光线、拥挤、遮挡、能力、注意力和伪装影响。看到一支军队不等于知道准确人数、统帅和目的。

## 10. 行动模型

### 10.1 行动协议

```yaml
action:
  id: action.instance.1001
  type: visit
  actor: person.player
  targets: [person.wang_yun]
  start_time: 480
  prerequisites:
    - actor_at_place
    - target_accessible_or_requestable
  phases:
    - travel_to_gate
    - request_entry
    - wait_for_response
    - conversation
  costs:
    time: dynamic
    stamina: low
  interrupt_policy: phase_boundaries
  visibility: local_observers
```

### 10.2 前置条件

前置条件读取客观状态，但行动者是否尝试行动可以基于错误认知。人物可能以为自己有通行文书，到了门口才发现已经失效。

### 10.3 结果

行动不直接返回“成功/失败”二元值，而是产生一组事件：

- 到达或未到达；
- 消耗时间和物资；
- 被谁观察；
- 获得了哪些信息；
- 关系和记忆如何变化；
- 是否生成后续计划或风险。

## 11. 事件与因果模型

### 11.1 不可变事件

事件创建后不修改。纠错通过补偿事件或重建场景完成。

```yaml
event:
  id: event.189.000001
  type: message_delivered
  time: 615
  location: place.luoyang.south_palace.gate
  actors: [person.messenger, person.recipient]
  causes: [event.order_issued.44, event.travel_completed.91]
  state_changes:
    - add_belief
    - close_commitment
  witnesses: [person.guard_3]
  rng_trace: null
```

### 11.2 因果边

每条因果边带类型：

- `enabled`：提供必要条件；
- `motivated`：改变人物决策权重；
- `informed`：提供或改变认知；
- `triggered`：直接触发反应；
- `constrained`：限制可选行动；
- `materially_supplied`：提供物资或人员；
- `prevented`：使另一个事件未发生。

这允许 `why` 查询区分“谁下令”“谁提供粮草”和“为什么人物愿意服从”。

### 11.3 状态投影

当前状态由最近快照和之后的事件投影得到。系统定期生成快照提高读档速度，但事件日志仍是历史变化的权威记录。

### 11.4 未发生事件

对玩家明显关注的计划，可以记录取消或错失：

```text
计划：午时会见卫宁
未发生原因：玩家仍在成皋路上
直接原因：昨夜渡口关闭导致行程延误
```

不能记录世界中所有“本可能发生”的事情，只追踪已形成承诺、计划或明确阈值的候选事件。

## 12. NPC 决策模型

### 12.1 决策输入

- 人物信念而非世界真相；
- 当前需求和长期目标；
- 性格与价值观；
- 官职职责和组织命令；
- 关系、记忆和承诺；
- 可达地点、可用时间和资源；
- 候选行动的主观风险和收益。

### 12.2 候选行动生成

候选行动由身份、环境和当前问题生成。系统不让每个人每次从所有动词中搜索。

```text
日程候选 + 紧急反应 + 组织任务 + 个人目标 + 社交义务
```

### 12.3 选择

第一版建议采用可解释的效用评分，而非黑箱模型。每次关键选择保存前几名候选及主要加减分原因，供开发者查询。

### 12.4 计划与承诺

人物可以建立多阶段计划，但计划不是锁定剧情。新消息、伤病、命令或资源不足可以使计划暂停、修改或取消。

## 13. 模拟精度

### 13.1 精度等级

| 等级 | 对象 | 模拟方式 |
|---|---|---|
| L0 | 与玩家同一具体地点、关键危机参与者 | 精确行动阶段和观察 |
| L1 | 同城人物、正在执行重要计划的对象 | 完整日程与事件调度 |
| L2 | 远方普通具名人物 | 按日或事件批处理 |
| L3 | 普通人口和背景经济 | 群体与统计更新 |

精度切换不得创造资源、瞬移人物或更改已经承诺的结果。提升精度时必须从已有状态展开，而不是重新随机生成一套人生。

## 14. 确定性

### 14.1 随机流

随机数按领域和实体拆分，例如：

- 天气；
- 旅行意外；
- 人物决策微扰；
- 市场撮合；
- 冲突判定。

增加一个无关 UI 随机调用不能改变董卓的行军结果。

### 14.2 回放输入

完整回放需要：

- 场景版本与内容哈希；
- 引擎版本；
- 所有随机流种子；
- 玩家命令序列；
- 外部调试干预记录。

## 15. 来源与运行时溯源

场景初始字段记录来源类型：

```yaml
provenance:
  kind: historical_claim
  claim_ids: [claim.189.wang_yun.henan_intendant]
```

或：

```yaml
provenance:
  kind: bounded_inference
  rule: luoyang_rainy_season_road_condition_v1
  input_claim_ids: [claim.189.summer.prolonged_rain]
  seed: 48192
```

运行开始后，字段变化引用事件 ID，不再继续假装由史料直接决定。

## 16. 世界不变量

首批必须自动检查：

1. 同一实体不能同时处于两个互斥精确地点。
2. 死亡或失能人物不能开始不允许的行动。
3. 物资转移前后数量守恒，允许显式损耗。
4. 消息不能早于其产生时间被接收。
5. 人物信念必须来自观察、推断、初始认知或消息。
6. 官职权限不能自动越过辖区和命令链。
7. 旅行时间不得小于路线和交通方式允许的理论下限。
8. 事件原因必须发生在结果之前或同一原子结算中。
9. 场景的所有假精确值必须有显式生成来源。
10. 相同输入必须产生相同事件序列。

## 17. 开发者查询接口

核心从第一版就应支持：

```text
where <entity> [at time]
who-controls <place|resource>
what-knows <person> <proposition>
why <event|state>
trace <message|order|resource>
history <entity>
plans <person>
compare <branch-a> <branch-b>
audit-provenance <scenario>
```

这些不是开发完成后再补的调试工具，而是复杂世界能够被验证的基础设施。

## 18. 首个垂直切片

以中平六年八月丁卯辰时为候选开局，世界模型最先打通：

1. 雒阳城内的地点与门禁；
2. 何进、袁绍、宦官等关键人物的认知和计划；
3. 外兵位置、命令和消息传播；
4. 一名普通玩家角色的移动、观察、交谈和传信；
5. 时间推进至戊辰宫变窗口；
6. 宫变发生、延迟、失败或偏转后的因果解释。

这一切片通过后，再扩展经济、完整职业和更长时间尺度。

- 人物效用评分的具体归一化方式；
- 事件日志的持久化格式；
- L2/L3 模拟与高精度展开的误差控制。

这些决定需要 MVP 规格和数据样例进一步稳定后再通过 ADR 确认。
