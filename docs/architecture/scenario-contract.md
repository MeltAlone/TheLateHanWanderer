# 场景数据契约

> 状态：0.1 草案，供首个垂直切片实现和修订

## 1. 目的

场景是已经完成历史主张选择、推断和玩法补全的可加载世界快照。模拟核心只消费场景，不直接查询史料库；但场景必须保留从每个初始值返回研究依据或显式假设的审计路径。

首个样例位于 `data/scenarios/189-luoyang-crisis/`。它是结构样例和验收夹具，不宣称其中所有空间、日程和数值已完成考据。

## 2. 组件边界

```text
manifest.json       版本、历法、随机种子、组件和缺口
world.json          地点、路线、组织、访问规则和初始控制
actors.json         人物、群体、身份、能力与初始位置
state.json          物品、信念、文书、承诺和活动计划
```

拆分只服务内容协作和增量加载；加载后形成同一个世界。领域对象不得持有 JSON、文件路径、SQLite 行或 CLI 文本对象。

## 3. ID 与引用

- ID 是小写 ASCII、点分命名空间，例如 `person.he_jin`、`place.luoyang.north_gate`。
- ID 一经发布不随中文显示名改变；改名只修改 `name`。
- 所有跨组件引用在加载前解析，不允许运行时保留悬空字符串。
- 具名人物、群体和物品使用不同前缀，避免精度提升时身份碰撞。
- 事件 ID 由运行时分配，不写入初始场景。

## 4. 来源覆盖

每个初始记录都包含 `provenance`。其 `applies_to` 列出该来源覆盖的业务字段；结构字段 `id`、`kind`、引用键和 schema 元数据不需要历史来源。一个记录混合多种依据时，使用多条来源覆盖不同 JSON 字段。

允许的来源类型只有：

| 类型 | 含义 | 必填引用 |
|---|---|---|
| `historical_claim` | 历史资料库中的主张 | `claim_ids` |
| `bounded_inference` | 在史实约束内选择的范围或状态 | `basis_claim_ids` 或研究切片引用 |
| `gameplay_assumption` | 为可玩性作出的可替换抽象 | `assumption_id` 和说明 |
| `simulation_seed` | 按固定种子从声明规则生成 | `stream`、`generator` |

未被任一 `applies_to` 覆盖的业务字段是验证错误。`historical_claim` 引用必须存在；其他类型也必须有可读理由，不能只写 `TBD`。

## 5. 随机配置

清单必须声明三项兼容性字段：

```json
{
  "rng": {
    "version": "xoshiro256ss.v1",
    "root_seed_hex": "18908D2400000001",
    "derivation": "sha256-le.v1"
  }
}
```

根种子是 1 至 16 位十六进制整数；加载后规范化为大写 16 位。随机流按领域和稳定实体 ID 派生，具体字节契约见 ADR-0005。更改算法、根种子或派生规则会改变模拟结果，必须同时更新场景版本和内容哈希。

## 6. 时间、距离和数值

- 场景时间使用自开局起的整数分钟 `minute`；负数只允许表示开局前的历史事件。
- 历法显示通过清单中的规范历法和映射表计算，不在各记录重复西历日期。
- 距离使用整数 `distance_li_q10`，表示十分之一里；持续时间使用整数分钟。
- 钱币、粮食、马料等采用具名整数单位，禁止无单位的 `amount`。
- 比例使用万分比 `basis_points`，概率阈值使用无符号定点整数。

这些单位未必是最终历史计量模型，但能防止语言或平台浮点差异污染确定性。

## 7. 命题、转述与冲突认知

`state.json` 的每个命题除 `id`、显示文本和客观状态外，可声明以下认知传播字段：

| 字段 | 含义 | 默认值 |
|---|---|---|
| `topic_id` | 多个相互竞争命题所属的同一议题 | 当前命题 `id` |
| `stance` | 命题在议题中的稳定立场标识 | `affirmed` |
| `retelling_variant_id` | 该命题发生转述失真时实际送达的命题 | `null` |
| `distortion_chance_bp` | 每次有来源转述发生失真的万分比概率 | `0` |
| `retelling_confidence_loss_bp` | 每次转述从发送者置信度扣除的万分点 | `0` |

`distortion_chance_bp` 和 `retelling_confidence_loss_bp` 必须位于 `0..10000`。非零失真概率必须提供存在的 `retelling_variant_id`，且源命题与变体必须具有相同 `topic_id`；不同 `stance` 表示人物可能同时持有的竞争判断。消息必须同时保存发送者陈述的原始命题和实际送达命题，并记录规则版本、确定性抽样和父消息，不能用直接改写所有人物信念的方式模拟传播。

没有显式填写这些字段的旧历史场景按“每个命题自成议题、立场为 `affirmed`、无失真、无置信度损失”加载，因此不会改变既有场景内容哈希和送信行为。冲突是运行时派生状态：同一人物对同一 `topic_id` 持有两个置信度大于零且 `stance` 不同的信念时形成，不在场景中预写“此人已经冲突”的全局结论。

## 8. 群体远方批处理

群体可选声明以下整数粮食字段，未声明时均为 `0`，不会自动排远方结算：

| 字段 | 含义 |
|---|---|
| `food_stock_units` | 开局时群体可用粮食库存 |
| `daily_food_production_per_thousand` | 每千人每日生产单位数 |
| `daily_food_consumption_per_thousand` | 每千人每日需求单位数 |

任一生产或消耗率非零时，加载器按 `distant-batch.v1` 从场景开局分钟起自动排每日批处理。运行时使用整数人分和余数结转，必须满足“期初库存 + 本期生产 = 本期消费 + 期末库存”和“累计需求 = 累计消费 + 当前未满足需求”；把同一时段拆成多个 tick 不得改变最终物料状态。群体人数发生升格或降格前必须先在当前分钟切账，避免新人数追溯影响此前区间。

同地、同组织且处于 L2 的具名人物可在批处理边界增加一次背景周期，但不得为 L3 人口逐个创建人物、行动或事件。所有结算游标、余数、累计账本、压力和 L2 周期必须进入快照；历史场景未声明粮食字段时保持原行为和内容哈希。

## 9. 人物与群体精度提升

群体不是许多匿名人物的永久替身。若一名守卒因玩家互动需要升级为具名人物，运行时必须：

1. 从群体数量中原子地减一；
2. 创建带 `promoted_from` 和稳定身份种子的具名人物；
3. 转移其已有位置、值勤、目击和持有物；
4. 保留从群体事件到新人物的因果边；
5. 重放时在同一事件点产生同一人物 ID 和属性。

降级只能将没有独立承诺、持有物、伤病、关系或未完成因果的临时人物合并回兼容群体。

## 9.1 运行时竞争访问队列

场景继续只声明访问规则、初始控制者和地点初始开闭状态。运行时按 `stable-access-queue.v1` 处理竞争：`may_queue` 不等于绕过资格要求；人物必须先满足组织身份、凭证或其他门禁要求，只有临时关闭和同分钟受理容量冲突可以进入队列。

队列每 5 分钟复查，最多等待 60 分钟；同一分钟每个可排队地点只允许一个请求进入。排序必须继承原始访问请求事件的稳定顺序，不能按人物 ID、字典顺序或重新入队时间排序。`AccessAndControlChange` 阶段先于队列复查，因此同刻地点开闭和控制者变化必须先被看到；若变化导致人物失去资格，下一次复查立即拒绝，不继续无意义等待。

快照必须同时保存地点当前控制者、最后受理分钟/人物、队列计数和未来复查事件。请求成功、超时、资格丢失或人物不可用时必须留下事件并释放队列计数；排队人物不得同时开始旅行或再排另一个地点。

## 10. 计划不是剧情脚本

初始计划描述行动者当前想做什么、相信什么、需要什么以及何时重新评估。计划可以因消息未到、权限变化、人物死亡、资源不足或新命令而取消、暂停或替换。

计划不得写成“到某时刻无条件杀死何进”或“确保董卓找到皇帝”。历史结果只能从通用行动、访问、传信、控制和决策规则产生。

每个计划必须声明：

- 所有者与当前阶段；
- 形成计划所依赖的信念；
- 必要条件和可选促进条件；
- 下一次评估时刻或触发事件；
- 取消条件；
- 对内容作者可读的意图说明。

## 11. 原子加载和规范化哈希

加载顺序是：

```text
读取清单 -> 读取全部组件 -> schema 验证 -> 引用和来源验证
-> 不变量验证 -> 规范化排序与序列化 -> 校验 content_hash -> 创建世界
```

规范化格式固定 UTF-8、LF、对象键按字典序、数组按 schema 声明决定是否保序。构建工具忽略清单自身的 `content_hash` 字段，对清单和所有组件计算 `sha256:` 哈希并写回；加载器必须重新计算并比对。开发模式可暂时接受 `pending-tooling` 并报告计算值，发布模式必须拒绝该值。

验证失败不得产生半个世界，也不得自动删除未知字段。错误格式示例：

```text
SCN-REF-001 actors.json $.persons[3].location
Unknown place id 'place.luoyang.inner_harbor'.
Declare the place in world.json or correct the reference.
```

## 12. 版本与迁移

schema 主版本变化表示需要显式迁移。迁移器读取旧文档、生成新副本、写入迁移报告并保留旧文件。内容版本变化不等于结构变化；规则版本变化则可能使旧事件日志不可继续。

存档必须嵌入或引用精确的场景内容哈希。仅有相同 `scenario_id` 不足以证明兼容。任何“尽量加载”模式只能用于开发者检查，不可覆盖原存档，也不能参与正式回放对比。
