# P6 初始精度与规模报告

> 状态：首批架构验证，不是正式 B1-B6 达标报告<br>
> 日期：2026-07-24<br>
> 引擎：`0.6.0-spike`；快照 schema：`0.6`

## 1. 本轮验证的问题

本轮只回答两个先决问题：L3 群体成员能否在不创造人口和随机人生的前提下成为可互动人物；空闲世界能否按到期事件推进，而不是按每分钟轮询全部人口。它不声称已经模拟两百万人口、100 万事件或 20 个长期分支。

实现使用四级精度：L0 近场人物、L1 同城或关键计划人物、L2 远方具名人物、L3 聚合群体。具名人物始终是独立领域对象；L3 只保存群体人数、位置、组织和升格 profile，不为每个人口当量创建对象。

## 2. 正确性契约

- 升格前验证来源群体非空，群体人数减一并创建一个稳定人物 ID，总人口不变。
- 身份种子由场景内容哈希、群体 ID 和单调升格序号经 SHA-256 派生，不消耗任何人物或世界随机流。
- 升格人物继承群体持有的信念，来源事件指向本次升格事件。
- 临时人物拥有独立物品、开放承诺、活动计划、行动、消息、独立信念或不同位置时，不允许降格。
- 干净降格删除仅由群体继承的临时信念，人物回并来源群体；事件日志保留升格和降格事实。
- 快照保存群体人数、精度、来源群体、身份种子和升格游标；加载后继续升格不会重用身份。

自动测试覆盖人口守恒、跨世界确定性、干净往返、消息阻止降格和快照续跑。当前结果为 46/46 通过。

## 4. 实测结果

| 负载 | 数据规模 | 时间 | 当前进程工作集 | 分配字节 | 正确性 |
|---|---:|---:|---:|---:|---|
| 确定性交付 | 100 次加载与交付 | 640.53 ms；6.405 ms/次 | 46,772,224 | 97,176,728 | 100 次事件指纹相同 |
| B1 缩小版 | 379 人口当量，空闲推进 30 日 | 6.87 ms | 47,161,344 | 2,576,064 | 只处理 719 个实际事件，指纹稳定 |
| B4 结构子集 | 1,000 次升格/降格 | 22.67 ms；0.023 ms/次 | 55,570,432 | 5,895,712 | 人口与物质状态指纹守恒 |

B1 的关键结果不是 6.87 ms 这个绝对值，而是 43,200 分钟的推进只结算 719 个到期事件。当前王允计划每 60 分钟复评一次，因此事件数并非零；调度器没有执行 `379 × 43,200` 次人物轮询。

B4 当前反复使用同一市场群体，升格后立即在没有独立互动的情况下回并。它证明稳定身份、事件记录、人口守恒和可审计降格成立，但尚未覆盖正式 B4 的随机群体选择、互动后保留、跨地点移动和批量资源核算。

## 5. 技术栈判断

当前没有证据支持更换 C#/.NET。核心仍只依赖 .NET BCL，场景、快照和 CLI 通过单向端口依赖核心；L3 没有展开为海量对象，事件推进也没有退化为全人口分钟轮询。未来若 SQLite、Godot、Unity 或 Web 客户端替换，领域规则和稳定快照 DTO 不需要随表现层重写。

这个判断是暂时的：B5 的百万事件追加与查询、B6 的分支隔离尚未验证，它们可能要求事件分区、只读基础快照、增量投影或数据库适配器，但不应先把数据库语义写进核心。

## 6. 下一步

1. 建立自动精度策略：玩家距离、活动计划、消息接触、未结承诺和因果负债共同决定 L0-L2，L3 只通过显式升格进入个人状态。
2. 实现 B2 单城危机，采样每次推进到玩家中断的中位数、p95、最大值和分配。
3. 实现 B3 消息扇出，验证 200 个载体产生真实消息谱系和局部信念，而不是全局同步。
4. 用 B5 决定事件归档、投影和增量快照边界，再用 B6 验证 20 个分支的可变状态与随机流隔离。
5. 将各负载改为独立进程、多样本报告；记录提交哈希、GC、峰值工作集和相对上次基准的变化。
