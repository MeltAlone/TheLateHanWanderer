# .NET 纵向切片技术尖峰

> 实现版本：`0.6.2-spike`<br>
> SDK：.NET 10.0.302<br>
> 日期：2026-07-24

## 1. 已打通链路

```text
场景 JSON
-> 结构化反序列化与跨文件引用校验
-> 规范化内容哈希
-> 纯领域 WorldState
-> CLI 查询/移动/交付/陈述/等待
-> 不可变事件与直接因果边
-> 稳定分阶段未来事件队列与精确等待中断
-> 版本化、按领域隔离的 xoshiro256** 随机流
-> 持久行动实例、路段位置与分阶段旅行
-> 旅行中断、恢复、取消和行动中存档
-> L0-L3 精度状态与 L3 群体成员确定性升降格
-> 快照保存/加载
-> 相同输入的事件指纹比较
```

实际玩家路径为：沈循从大将军府步行至司隶校尉署，向袁绍交付封记，返回大将军府向李文回报。总耗时 54 分钟，产生 11 个按序事件并关闭两项承诺；回报包含消息创建、送达和信念更新。

## 2. 解决方案边界

| 项目 | 当前职责 | 允许依赖 |
|---|---|---|
| `LateHan.Core` | 世界状态、路径、行动、调度、随机流、事件和确定性指纹 | .NET BCL |
| `LateHan.Scenarios` | JSON DTO、数据验证、规范化哈希和领域构建 | Core |
| `LateHan.Persistence` | 版本化快照 DTO 和原子文件写入 | Core |
| `LateHan.Cli` | 命令解析和中文文本呈现 | Core、Scenarios、Persistence |
| `LateHan.Tests` | 行为、确定性和快照测试 | Core、Scenarios、Persistence |
| `LateHan.Benchmarks` | 无界面重复运行和指纹检查 | Core、Scenarios |

核心项目没有引用 `System.Text.Json`、文件路径、数据库或 CLI 文本。当前最短路径按整数分钟计算，并用稳定 ID 处理相同成本的排序。

## 4. 已实现的兼容性约束

- 场景哈希忽略对象键顺序、无意义空白以及清单自身的 `content_hash` 字段。
- 世界状态保存场景版本、规则版本、RNG 版本、引擎版本和内容哈希。
- 快照使用稳定 DTO，不序列化领域对象图。
- 快照先写临时文件再原子替换目标文件。
- 当前尖峰只接受完全匹配的引擎版本；正式迁移器尚未实现。
- 无效移动在验证阶段失败，不推进时间，也不产生事件。
- 同刻队列使用 `(due_minute, phase, stable_subject_id, sequence)`，整批结算后才暂停。
- 快照 schema `0.7` 额外保存群体、人物精度、升格来源、身份种子、升格序号和待重评人物脏集。
- `dev rng` 只在副本上预览；`dev schedule` 留下外部干预事件并标记回放。
- 旅行使用稳定行动 ID 和逐路段完成事件；中断保存整数进度，恢复可更换交通方式。
- 运行中和中断行动均可保存；加载后的完成状态、事件指纹、队列和随机游标与连续运行一致。

## 5. 已实现的 P4 闭环

- 场景信念和计划加载为运行时状态；初始复评事件进入统一调度队列。
- 正式报告交付后产生 `belief_updated`，计划在同一分钟复评并调用通用旅行行动。
- NPC 旅行完成产生 `plan_completed`，事件原因链连接报告、信念、复评、旅行和抵达。
- 快照保存并恢复计划挂起事件、关联行动和信念来源，续跑与连续运行保持相同指纹。

## 6. 已实现的 P5 闭环

- 场景访问规则、人物组织身份、凭证范围与有效期、地点开闭状态映射为纯领域对象。
- `enter` 验证邻接关系并消耗五分钟通报时间；允许、拒绝和中断均留下事件与原因。
- `BeginTravel` 和抵达结算复用门禁判定；同刻 `access_and_control_change` 可以阻止随后发生的抵达。
- 口头陈述形成可持久化消息，接收者信念引用送达事件，转述消息保留父消息 ID。
- 交付和交谈在耗时期间处理世界事件；接收者离开时不产生跨空间转移或认知更新。

## 7. 已实现的 P6 精度基础

- 具名人物使用 L0-L2，人口群体固定为 L3；L3 不展开为海量个人对象。
- 群体升格使用稳定单调 ID 和由场景内容派生的身份种子，不依赖容器遍历顺序或普通随机流。
- 升格继承群体可知信念；独立消息、信念、持有物、承诺、计划、行动或位置偏离都会阻止降格。
- 1,000 次干净升降格往返保持总人口和物质状态指纹不变；升格与降格事件仍保留在因果日志中。
- CLI 提供 `groups`、`detail`、`dev promote` 和 `dev demote`，快照可恢复临时人物身份与人口游标。
- `attention-and-causal-debt.v1` 按玩家同地/相邻、活动行动与计划、开放承诺和七日内消息评估 L0-L2，并将每次变化的理由写入事件。
- `dev rebalance-detail` 可显式重平衡全世界或单个人物；评估按稳定人物 ID 排序，不依赖字典遍历顺序。
- benchmark 专用合成工厂可以稳定创建 50 个 L0、500 个 L1、200 万 L3 人口当量、50 地点和 200 消息载体，不污染历史场景内容。
- `b2-scale` 验证 540 个并发旅行行动、增量脏集精确消费、人口守恒和 L3 不展开；`b3-scale` 验证 200 条消息、150 条父链接和逐接收者消息来源信念。
- 目标结构负载使用 1 次热身和 5 次样本，分别报告构造与模拟时间、分配、样本工作集、GC 和确定性指纹。
- 人物位置更新同时维护地点/路段空间索引；玩家移动只令旧、新注意空间及其邻接地点失效，普通人物只令自身失效。
- 行动、计划、承诺、消息和消息保留期到期均会增量标脏；脏集进入 schema `0.7` 快照，加载后空间索引由位置重建。
- 精度刷新保持显式边界，不改变原有旅行、访问、交付和交谈动作的核心事件序列。

## 8. 尚未实现

- 多 NPC 计划协调、资源竞争和更复杂的计划复评；
- 群体传言升格、文本变体、主动查证和复杂置信度合成；
- 门禁请求、交付和陈述像旅行一样保存于行动中途的通用持久行动协议；
- 正式客户端和世界调度器采用何种稳定边界自动消费精度脏集；
- 事件溯源投影、增量快照和存档迁移器；
- 汉历时辰显示、疲劳、马匹授权和路况扰动；
- B2 混合消息、访问、计划变更和远方低频运行，以及当前目标人口核心的 `< 250 ms` 性能预算；
- B3 转述失真、竞争来源和冲突信念语义；
- 正式 B1/B4，以及 B5、B6 合成世界性能基准。

下一实现阶段应先定位 B2 的事件与分配热点并补齐 B2/B3 语义，再用长期日志与分叉负载决定事件持久化架构；不能先增加图形界面。
