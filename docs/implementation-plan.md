# 世界机器实施计划

> 状态：执行中<br>
> 最近更新：2026-07-24<br>
> 当前实现：`1.0.0-spike`

## 1. 这份文档负责什么

本文件是项目从设计与历史资料走向可玩动态世界的总执行入口，回答三个问题：已经完成了什么、当前真实能力到哪里、接下来按什么顺序实现和验收。

玩法原则以[世界模拟总设计](design/overview.md)为准，命令与行为以[命令行 MVP 规格](design/mvp-spec.md)为准，领域边界以[世界模型](architecture/world-model.md)为准，具体技术选择由[架构决策记录](decisions/README.md)约束。本计划只安排工作，不覆盖这些上位契约。

## 2. 最终目标

建立一台玩家可以从个人视角进入的汉末世界机器：时间和空间持续约束所有人；人物依据有限认知、身份、资源和动机形成计划；行动需要真实耗时并可能失败或中断；消息、承诺和物质变化留下可查询因果；相同场景、随机种子和命令必须确定性重放。

第一阶段完成标志不是“拥有很多命令”或“做出图形界面”，而是[雒阳四日验收规格](../tests/specs/189-luoyang-crisis.md)中的核心路径能够由通用规则运行，并满足[世界规模预算](../tests/performance/world-scale-budgets.md)的阶段门槛。

### 3.2 C#/.NET 纵向切片

### 3.3 世界机器 `0.2` 基础

- 已实现持久未来事件队列，稳定排序键为 `(due_minute, phase, stable_subject_id, sequence)`。
- 已实现同一分钟完整批次结算，不依赖集合插入顺序，也不给玩家隐藏优先权。
- 已让 `wait` 按事件边界推进；四小时等待可在第 95 分钟精确中断，剩余 145 分钟不发生。
- 已实现 `xoshiro256ss.v1` 和 `sha256-le.v1` 领域隔离随机流，固定参考向量和跨流独立性测试。
- 快照 schema `0.2` 已保存未来事件、序号游标、根种子、随机流状态、抽取次数和回放修改标记。
- 已加入只读 RNG 预览、队列查看和带 `debug_intervention` 因果记录的调试排程。
- 当前自动测试为 19 项；构建、格式、场景校验、JSON、Markdown 链接和 NuGet 漏洞检查全部通过。

### 3.4 持久行动与旅行 `0.3`

- 已实现稳定 `ActionInstanceState`、行动序号、运行阶段、开始原因和旅行专用负载。
- 人物位置已严格区分“在地点”和“在路段”；中断时保存路线、方向和整数千分比进度，不回到起点或提前抵达。
- `Move` 已改为 `BeginTravel -> 路段事件 -> AdvanceAction` 的便捷包装；多路段旅行逐段调度并留下开始、完成和抵达因果。
- 已支持旅行中断、原方式或换方式恢复、取消，以及运行中或中断点保存/加载。
- 旅行风险使用 `travel-risk:action-id` 隔离随机流和整数阈值，事件记录抽取值、阈值、流键和结果。
- 同刻高优先级失能会立即改变行动状态并移除抵达事件，但玩家界面仍在同刻批次完整结算后暂停。
- 已证明目标人物可以在玩家旅行期间先离开；玩家抵达后交付失败，已付旅行时间不回滚。
- CLI 已能分别执行 `travel start`、`advance`、`actions`、`resume` 和 `cancel`，可在行动边界保存与加载。
- 当前自动测试为 41 项，覆盖运行中存档、中断存档、换步行恢复、取消、途中等待、共享时间轴、同刻冲突、自主 NPC、门禁和消息闭环。

### 3.5 运行时信念与自主 NPC `0.4`

- `BeliefState` 和 `PlanState` 已进入 `WorldState`，保存持有人、命题、置信度、来源事件、计划阶段、复评时间和关联行动。
- 王允的 `written_report_inspection.v1` 计划先等待正式报告；`Deliver` 完成普通物品转移后更新信念，并在同一分钟调度计划复评。
- 复评只读取计划所有者持有的信念与报告，不读取北门全局状态；满足条件后调用通用 `BeginTravel`，旅行完成再以 `plan_completed` 闭合因果链。
- 快照 schema 已升级为 `0.4`，保存文书元数据、信念、计划、挂起复评事件和关联行动。

### 3.6 访问、消息与认知 `0.5`

- 访问规则、人物组织身份、凭证适用范围和有效期、地点开闭状态已经进入运行时领域状态。
- `enter` 只允许请求相邻地点；非相邻请求不耗时，受限地点在五分钟通报后明确允许、拒绝或中断，并且拒绝结果不泄露内部人物状态。
- 普通旅行不能绕过门禁；同一分钟的权限变化先于抵达结算，已经付出的旅行时间不会因门禁收紧而回滚。
- 面对面陈述现在形成 `MessageState`，记录发送者、接收者、命题、置信度和上游消息；只有实际收到消息的人更新信念。
- 文书交付和口头消息在耗时期间都会处理世界事件；目标离开或玩家被中断时，不发生物品转移、消息送达或信念同步。
- 快照 schema 升级为 `0.5`，保存访问规则、人物身份、凭证、地点门禁状态和消息谱系。

### 3.7 精度与群体升降格 `0.6`

- 已将具名人物的 L0-L2 精度和 L3 聚合群体映射为纯领域状态；当前场景包含 15 个具名人物、7 个群体和 379 人口当量。
- 群体成员升格会原子减少群体人数，使用内容哈希、群体 ID 和单调序号派生稳定身份，不消耗普通随机流，也不会凭空增加人口。
- 临时人物只有在没有独立物品、承诺、计划、行动、消息、信念且回到来源群体位置时才能降格；否则明确拒绝，不静默丢弃因果。
- 快照 schema 升级为 `0.6`，保存群体、人物精度、升格来源、身份种子和升格序号；保存/加载后身份与人口游标保持一致。
- 已加入 B1 缩小版和 B4 结构子集入口：30 日空闲推进只处理 719 个实际事件；1,000 次升降格往返保持人口与物质状态指纹守恒。
- 该阶段完成时自动测试为 46 项；P6 的首批结果和未覆盖边界记录在[P6 精度与规模报告](architecture/p6-scale-report.md)。

### 3.8 注意力与因果负债精度策略 `0.6.1`

- 已实现 `attention-and-causal-debt.v1`：玩家及同地人物为 L0，相邻人物、活动行动/计划、开放承诺和七日内消息参与者至少为 L1，其余具名人物可降为 L2。
- 每次精度变化产生 `actor_detail_level_changed`，记录策略版本、旧/新精度和判定理由；相同世界按稳定人物 ID 顺序重平衡得到相同事件指纹。
- CLI 新增 `dev rebalance-detail [person-id]`，可显式评估全世界或单个人物；当前重平衡仍由调用者触发，尚未接入每种世界状态变化后的增量失效队列。
- 已增加 B2 单城危机和 B3 消息扇出的缩小入口：12 名城内人物并发行动保持人口守恒；3 个命题经 14 名载体产生 42 条消息和 39 条父消息链接。
- 该阶段完成时自动测试为 50 项；B1-B4 缩小结果及正式负载缺口记录在[P6 精度与规模报告](architecture/p6-scale-report.md)。

### 3.9 增量精度失效与空间索引 `0.6.2`

- `WorldState` 已维护由地点/路段到稳定人物 ID 的派生索引，以及有序的 `DetailDirtyActorIds` 脏集；人物移动通过统一状态入口同步更新索引。
- 玩家改变位置时只标记旧、新注意空间及其邻接地点的人物；普通人物移动只标记本人。行动、计划、承诺和消息变化也只把直接相关人物放入脏集。
- 七日消息保留期现在有确定性到期事件；到期时重新标记发送者和接收者，不依赖每分钟扫描全部消息。
- `RebalanceDirtyActorDetailLevels` 只评估脏人物并在成功后清除相应标记；CLI 可用 `dev detail-dirty` 检查队列，用 `dev rebalance-detail dirty` 显式刷新。
- 快照 schema 升级为 `0.7`，保存待重评人物；地点/路段索引由人物位置在加载时重建，不重复持久化派生数据。
- B2 缩小版的两次刷新总计只评估 24 个人次，而不是每个边界反复全扫世界；该阶段完成时自动测试为 54 项。

### 3.10 B2/B3 目标结构负载

- benchmark 工程新增确定性合成世界工厂，不改动历史场景：B2 创建 50 个 L0、500 个 L1、50 个地点和一个 200 万人口当量 L3 群体；B3 创建 50 个地点和 200 名消息载体。
- 新增 `b2-scale`、`b3-scale` 和 `scale` 入口。每项执行 1 次热身、5 次全新世界样本，分别报告场景构造与模拟的中位数、p95、最大值、标准差、分配、样本工作集和各代 GC 次数。
- B2 让 540 名非目标地点人物同时旅行，推进 12 小时并严格核对两次脏集刷新、15,502 个事件、人口守恒和 L3 不展开；五次事件指纹一致。
- B3 让官方命题经过 50 个地点形成 200 条真实消息和 150 条父消息链接；每名载体的信念都能回指送达事件，没有批量认知写入；五次事件指纹一致。
- B2 优化前五样本 p95 约 535 ms，高于 `< 250 ms` 预算；B3 达到目标拓扑，但尚无复述失真和冲突信念规则。二者都不是完整 B2/B3 达标。

### 3.11 B2 热点优化与预算复测

- CPU 采样显示主要成本来自重复最短路径搜索、全世界行动扫描和最终事件指纹审计；高分配也使 GC 成为显著成本。
- `WorldState` 在构造或快照加载时重建地点到稳定路线遍历边、人物到按序行动列表的派生索引；查询不再反复扫描全图路线或全世界行动。
- 事件和调度事件详情改为一次有序只读快照；事件指纹利用既有事件顺序，并使用栈缓冲或共享数组池降低 UTF-8 编码分配。
- benchmark 将模拟本体与事件指纹审计分开计时和统计分配。最近一次 B2 五样本模拟中位数/p95 为 175.917/184.432 ms，分配中位数 45,130,560 bytes。
- 优化后连续三次五样本 p95 为 227.619、175.088 和 184.432 ms，均低于 `< 250 ms`；15,502 个事件、人口守恒、L3 不展开和事件指纹均保持不变。
- 在本批结束时，目标人口核心已经满足当前参考机预算，但完整 B2 仍缺传信、访问、计划变更、远方低频运行和多个玩家中断，不能据此宣称 B2 达标。

### 3.12 B2 混合城市危机负载

- 新增独立 `b2-mixed`，保留 `b2-scale` 作为纯人口与路径基线；`scale` 现在依次运行 B2 人口核心、B2 混合结构和 B3 消息拓扑。
- 混合负载在 50 个 L0、500 个 L1、200 万 L3 人口当量和 50 个地点上组合 540 人并发旅行、2 次玩家中断与恢复、20 人公开地点往返、40 条有谱系消息、10 个自行完成的计划和 3 个远方低频 tick。
- 每个世界除总模拟时间外还记录两次“推进至下一玩家中断”；连续三轮五世界样本的中断 p95 为 28.482、36.287 和 23.940 ms，均低于 MVP `< 100 ms` 与 B2 `< 250 ms` 门槛。
- 最近一次总模拟中位数/p95 为 105.201/143.360 ms，分配中位数 45,174,432 bytes；15,743 个事件、消息谱系、计划状态、位置、脏集、人口和 L3 不展开均通过五次确定性核对。
- 自动测试新增同一旅行跨两次玩家中断恢复，当前为 55 项。混合结构已覆盖，但远方 tick 尚未改变群体状态，访问尚无拒绝/排队竞争，计划尚无资源冲突、替换或取消，所以正式 B2 仍未宣告完成。

### 3.13 B3 可版本化转述与冲突认知

- 命题新增稳定 `topic_id` 和 `stance`，同一议题可拥有多个竞争立场；旧场景默认以命题自身 ID 为议题、立场为 `affirmed`，历史场景内容哈希不变。
- `retelling-distortion.v1` 允许命题声明转述变体、万分比失真概率和每次转述的置信度损失；随机抽样按消息稳定 ID 隔离，重复运行结果一致。
- 消息同时保存发送者原始命题与实际送达命题，并记录传播规则版本、失真抽样和父消息，因此任何失真都能从事件与消息谱系审计。
- 同一人物对同一议题持有置信度大于零且立场不同的信念时，运行时派生冲突认知；首次形成冲突产生 `belief_conflict_detected`，人物计划和认知查询仍不读取世界真相。
- 快照 schema 升级到 `0.8`，完整保存命题传播规则与消息审计字段；保存/加载后冲突、谱系和确定性保持一致。
- 新增 `b3-conflict` 目标语义负载：50 地点、200 载体、300 条消息、150 条父链接、100 次失真、100 个冲突持有人和 100 个冲突事件；五次指纹一致。
- 当前 Release 构建零警告，58 项自动测试通过。`b3-scale` 继续作为纯拓扑基线，`b3-conflict` 单独暴露认知语义成本；达到这两项不等于完整 B1-B6 已达标。

### 3.14 B2 有状态远方批处理

- 新增 `distant-batch.v1`：群体可配置粮食库存、每千人每日生产和消费，加载后幂等排程低频 `remote_world_tick`，结算成功后自动续排。
- 结算使用整数人分和余数结转，保存累计生产、需求、消费、当前未满足需求与压力；每个批次都验证库存和需求账本守恒，同一总时段分批或合批得到相同物料状态。
- 群体升格或降格前先按旧人数切账，避免人数变化追溯污染此前区间；拥有远方背景周期的临时人物不能直接降格丢失独立因果。
- 与群体同地、同组织的 L2 具名人物在远方边界增加一次可审计背景周期，L3 人口仍不展开为个人对象或逐分钟行动。
- 快照 schema 升级到 `0.9`，保存远方账本、余数、结算游标、未来 tick 和 L2 周期；非零场景开局分钟不会重复结算开局前时间，加载后续跑与连续运行一致。
- `groups` 和 `detail` 可观察库存、累计生产/消费/缺口、压力、结算分钟和人物远方周期。B2 混合负载三次结算后满足 `500万 + 90万 = 100万 + 490万`，总人口当量保持 2,000,550。
- 当前 Release 构建零警告，64 项自动测试通过；最近一次独立 B2 混合负载中位数/p95 为 145.180/164.583 ms，玩家中断中位数/p95 为 21.698/38.307 ms，仍低于阶段预算。

### 3.15 B2 确定性竞争访问队列

- 新增 `stable-access-queue.v1`。人物仍先消耗五分钟通报时间；只有已满足身份/凭证要求、但因地点临时关闭或同一分钟受理名额已占用而受阻的请求可以排队，无资格者立即明确拒绝。
- 队列每 5 分钟复查，最多等待 60 分钟；成功、人物不可用、资格丢失和超时都会留下明确事件并原子释放队列计数。排队人物不能开始旅行或重复请求另一地点。
- 同一分钟每个可排队地点只受理一个请求；稳定主体使用原始 `access_requested` 事件 ID，因此严格按请求顺序，而不是按人物 ID 或集合遍历顺序插队。
- `AccessAndControlChange` 阶段先于队列复查，同刻开门、关门或控制者变化会影响随后决策；运行时控制者、最后受理分钟和人物均进入地点访问状态。
- 快照 schema 升级到 `1.0`。队列由地点计数和未来 `access_queue_review` 事件共同持久化，保存/加载后同刻排序、请求顺序与连续运行指纹一致；CLI 新增 `access <place-id>` 查询规则、开闭、队列、控制者和最后受理。
- B2 混合负载加入 2 个竞争排队请求，仍完成 20 次往返；最近一次独立五样本中位数/p95 为 158.564/166.617 ms，玩家中断中位数/p95 为 26.216/31.349 ms，15,751 个事件的固定指纹为 `sha256:5e09cde80c680c5563d1603d08f780ac64151ad7d395ffe9fd6110a998f18252`。
- 当前 Release 构建零警告，68 项自动测试通过；场景内容哈希保持不变，格式、场景校验和依赖漏洞扫描通过。

### 3.16 B2 计划资源仲裁

- 新增 `exclusive-plan-resource.v1`。计划可声明多个稳定资源键、非负优先级和是否允许替换低优先级持有者；资源集合按稳定 ID 排序并一次性获取，不允许部分加锁。
- 同刻计划仍按统一调度键确定性处理。资源被占用时产生 `plan_resource_conflict` 并按复评间隔等待；只有显式允许替换且优先级严格更高时，才取消全部冲突计划后获取资源。
- 计划完成、显式取消、关联旅行取消和启动失败都会产生原因事件并释放全部锁。启动失败回到活动状态并重排，已取消旅行保留真实路段位置，不回滚或瞬移。
- 快照 schema 升级到 `1.1`，保存计划资源声明、优先级、替换策略和当前锁；加载时拒绝未知计划、非运行计划、未声明资源或缺少获取事件的非法锁。
- CLI 的 `plans` 显示资源声明与当前锁，`plan cancel <plan-id> [reason]` 可显式取消。B2 混合负载形成 8 个完成、2 个取消、2 次冲突和 1 次替换，结束时无锁泄漏。
- 最近一次独立五样本中位数/p95 为 155.716/170.151 ms，玩家中断中位数/p95 为 26.673/31.964 ms；15,770 个事件的固定指纹为 `sha256:9b154e009144b646f2db279168dcecad43b487338fca36a4066e5cf739229819`。
- 当前 Release 构建零警告，73 项自动测试通过；历史场景内容哈希保持不变，格式、场景校验、CLI 手测和依赖漏洞扫描通过。

### 3.17 B4 目标交互负载

- 合成世界创建分布在 50 地点的 100 个 L3 群体和 100 万群体人口，以及每地一名消息锚点；不改动历史场景。
- 1,000 次升格由 `b4-group-selection` 隔离随机流按稳定迭代 ID 抽取群体，验证身份不复用、随机选择跨样本一致且 L3 不展开。
- 700 名临时人物直接回并，200 名跨相邻地点往返后回到来源群体再合并，100 名因实际面对面消息产生独立信念与谱系而必须保留；最终总人口当量守恒，群体人口只减少保留的 100 人。
- 最近一次独立五样本中位数/p95 为 58.258/65.566 ms，分配中位数 10,268,952 bytes；3,000 个事件的固定指纹为 `sha256:9b2b830dde11c3183e738e60b81e678a0e3a5986cabe6d5c9cf90b9b7c6da03f`。
- 当前负载证明正式 B4 的目标语义与结构预算，不改变引擎或快照协议；Release、73 项测试、场景校验和依赖漏洞扫描继续通过。

### 3.18 B1 目标空闲世界

- 新增独立 `b1-scale`，创建 50 L0、500 L1、20,000 L2、100 个 L3 群体和 200 万 L3 人口，完整覆盖规模预算中的人物精度层级。
- 30 日内预置 10,000 个普通到期事件，并让 100 个群体每日结算一次远方粮食与关联 L2 周期；最终处理 3,000 个远方 tick、3,000 个 L2 批次和 10,000 个普通事件，而不是执行“人口 × 43,200 分钟”轮询。
- 远方批处理改为复用地点到稳定人物 ID 的派生索引，再按 L2 和组织过滤；避免每个群体 tick 扫描全部 20,550 名具名人物。索引仍从状态重建，不进入快照或事件协议。
- 所有 20,000 名 L2 恰好推进 30 个背景周期；100 个群体的生产、需求、消费和库存守恒，30 日后只保留 100 个下一日 tick，总人口当量保持 2,020,550。

### 3.19 B5 百万事件长期归档

- 新增独立于 `LateHan.Core` 的 `WorldEventArchive` SQLite 适配器；核心只新增可流式使用的标准事件指纹器，不认识数据库、表或 SQL。
- 归档按严格连续序号分批事务追加，保存完整事件载荷和独立因果边索引；支持按 ID 直接读取、有限深度/数量的 `why`、检查点载荷、检查点后尾日志恢复和从头审计。
- 检查点只约定事件游标、事件 ID、指纹和调用方提供的投影字节，不把世界 DTO 或数据库模型绑死；恢复若尾日志超过声明上限会失败，不会静默截断。
- 压缩备份先使用 SQLite 在线备份 API 生成一致性副本，再以 GZip 压缩，避免复制带 WAL 的活跃数据库；原生依赖显式升级到无已知漏洞的 `SQLitePCLRaw 3.0.4`。
- `b5-scale` 流式生成 100 万事件，每 25,000 条创建检查点。最近一次追加 8.692 秒、直接查询 4.820 ms、8 层 `why` 0.785 ms、恢复 0.340 ms、全量审计 3.046 秒；压缩后 42,496,346 bytes。
- 全量审计指纹 `sha256:b15d039a114b9e3b1f0ef715a6cb1c14b706b9719db7bf38805a05c777e396e9` 与生成期指纹一致；Release 零警告，76 项测试、场景校验、格式和依赖漏洞扫描通过。

## 4. 当前真实边界

当前内核已经证明“行动可以在运行中的世界里分阶段发生”，但还不能称为自行运行的世界，主要缺口是：

- 交付和陈述仍在一次同步调用中完成，尚未迁入统一持久行动协议。
- `state.json` 中的信念、人物计划、计划资源声明、地点门禁与消息载体已进入运行时领域状态；群体传言升格和跨组织目标协调仍未实现。
- 领域事件处理器目前覆盖旅行、地点访问/控制变化、访问队列、消息送达和测试用人物迁移；组织级控制与资源市场处理器仍未实现。
- 当前只有王允的一个通用规则计划会自行复评并通过与玩家相同的旅行规则改变世界。
- 访问请求仍以同步五分钟通报开始，但等待队列已通过未来事件持久化；通报中的前五分钟尚未拥有像旅行一样可单独保存于中途的通用行动实例。
- 骑马旅行已有风险与交通方式耗时，但马匹授权、实际持有转移、马料数量和伤病状态仍等待资源与访问规则。
- 已有由位置、行动、计划、承诺和消息变化维护的持久化增量脏集；为了保持玩家动作事件协议稳定，脏集目前在显式开发命令或未来调度边界刷新，不把精度事件强行混入每个玩家动作结果。
- 已有 B1-B5 可执行目标负载，以及有状态远方批处理、竞争访问队列、计划资源仲裁和百万事件长期归档；B6 分支隔离仍未实现。
- 长期归档已有通用检查点载荷和尾日志恢复，但运行中的 `WorldState` 尚未自动把冷事件移出内存；完整世界增量快照、快照迁移器和日志分区仍未实现。

因此，下一步不扩地图、不批量增加人物命令、不进入 Unity/Godot，也不先制作图形界面。

## 6. P3：持久行动与可中断旅行

本阶段已经完成。`Move` 不再直接跳转时间，玩家和未来 NPC 的旅行都表示为世界中的持久对象。

### 6.1 领域状态

- 新增稳定 `ActionInstanceState`，保存行动 ID、行动者、种类、状态、开始时间、当前阶段和直接原因。
- 新增旅行负载，保存起点、终点、路线、交通方式、当前路段、已行进分钟、已付成本和下一阶段事件。
- 明确位置表达：人物在地点或在某条路段上，二者互斥；中断时不得瞬移回起点或提前到终点。
- 行动状态至少支持 `scheduled`、`running`、`interrupted`、`completed` 和 `cancelled`。
- 快照保存运行中行动及其已付成本、队列事件和恢复所需游标。

### 6.2 引擎协议

- 将耗时命令拆为“验证并开始行动”和“推进到完成或中断”，避免一次调用隐藏全部中间状态。
- 旅行开始、路段完成、抵达和意外通过稳定事件种类处理器改变领域状态。
- 玩家与 NPC 使用同一旅行入口；CLI 只负责把同步交互包装在领域协议之外。
- 中断保留已经发生的时间、位置、物资和事件，不做命令级回滚。
- 支持从中断状态继续、改为步行或取消；每种选择留下新的原因边。

### 6.3 P3 验收

- 已用固定旅行风险流令骑马 40 分钟后发生马伤；人物和所持文书停在同一路段，40 分钟不回滚。
- 已验证旅行运行中和中断点保存；加载后继续与未重启运行具有相同状态、事件和随机流游标。
- 已排定早于抵达的人物离开事件；玩家到达后不能交付，物品和开放承诺保持原状。
- 已验证无效移动不推进时间、不创建事件，也不消耗行动或调度序号。
- 原有 54 分钟送信路径仍通过；消息显式化后共 11 个事件，直接单路段旅行继续只产生开始和完成两个核心事件。

## 7. P4：第一个自主 NPC 闭环（已完成）

本阶段已完成。只实现一个可解释的计划闭环，没有铺开完整 AI。

- 将场景中的运行时信念和计划映射进 `WorldState`，保留持有人、依据、阶段、复评时间和取消条件。
- 首选王允的城门报告计划作为低风险样例：等待报告、接收消息、更新信念、复评计划、产生检查或等待行动。
- 计划评估只读取人物可知状态，不读取全局真相；所有随机微扰使用人物决策专属流。
- 计划结果只能调用通用移动、访问、交付、陈述和等待规则，不能硬编码“历史必然发生”。
- 新消息、权限变化、资源不足或人物移除必须能够使计划暂停、替换或取消。

P4 的完成证据是一条可查询因果链：初始信念与计划 -> 复评触发 -> 行动选择 -> 分阶段行动 -> 状态变化 -> 新信念或后续计划。保存/加载和无关随机调用不能改变结果。

## 8. P5-P7 后续顺序

P5 已完成首个地点访问、门禁、消息载体和信念更新闭环。人物“知道什么”建立在真实接触和传播路径上，不会退化成全局变量同步。

P6 已完成十三批：L0-L3 状态与守恒升降格、注意力/因果负债精度评估、持久化增量脏集和空间索引、目标结构与热点优化、混合城市危机、转述失真与冲突认知、远方批处理、竞争访问队列、计划资源仲裁、B4 目标交互、B1 目标空闲世界，以及 B5 百万事件归档。下一步用 B6 验证只读基础、分支可变状态、事件尾日志和随机流隔离；之后进入 P7 雒阳四日可玩整合。

## 9. 每个阶段的完成标准

任何阶段只有同时满足以下条件才算完成：

1. 通用领域规则中没有硬编码某个历史人物必须得到历史结果。
2. 新的耗时与状态变化由事件表达，重大结果有直接原因，可查询且可重放。
3. 相同场景、命令和随机状态重复运行得到相同事件与状态。
4. 快照保存全部新增可变状态；加载后续跑与不中断运行一致。
5. 无效输入不产生部分副作用；中断则保留已经真实发生的副作用。
6. 自动测试覆盖主路径、失败路径、同刻冲突和存档边界。
7. Release 构建零警告，格式、场景、JSON、Markdown 链接和漏洞检查通过。
8. 文档更新真实能力与剩余边界，必要的长期语义以 ADR 固定。

## 10. 计划维护规则

- 每完成一个阶段，更新“已经完成”“当前真实边界”和阶段状态，不只在提交记录中描述进展。
- 若验收暴露架构假设错误，先修订本计划与相应契约，再扩大实现范围。
- 新需求应归入已有阶段；若会改变多个模块的长期语义，先建立 ADR。
- 性能优化必须由规模基准驱动，不以牺牲确定性、因果或存档兼容为代价。
- 历史内容扩张必须继续经过研究主张和场景构建流程，不能直接硬编码进模拟规则。
