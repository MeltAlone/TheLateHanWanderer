# 《汉末浮生》正式游戏实施计划

> 状态：执行中
>
> 最近更新：2026-07-25
> 正式项目：`game/LateHan.Game.slnx`

## 已经完成

- 冻结旧分钟级洛阳原型的产品扩张，将其保留为技术验证和回归参考。
- 明确正式产品为日/旬/月推进的三国个人生涯与动态历史模拟。
- 建立独立的 Domain、Simulation、Content、Persistence、Avalonia App 和测试项目。
- 实现 360 日历、上中下旬判断和逐日推进。
- 实现战略地点、道路、坐标、地点类型和城内地点两层空间结构。
- 实现统一人物模型、六项能力、身份标签、性格、动机和位置。
- 加入 8 个战略地点、首批城内地点、24 名具名人物和 3 种开局身份。
- 实现旅行、城内移动、拜访、打听、训练、谋生、休整和 NPC 周期迁移。
- 实现旬边界日志以及版本化 JSON 存档和读档。
- 实现全中文可点击 Avalonia 界面，玩家不需要输入内部 ID。
- 完成自动测试和真实窗口点击冒烟：选身份、进入太学、选择蔡琰、拜访后日期推进一日且关系增加。
- 当前自动测试共 16 项通过，正式项目 Release 构建 0 警告、0 错误；旧技术原型 88 项回归测试继续通过。

## 当前真实边界

当前版本是“产品方向纵向切片”，不是功能完备的游戏。

- 地图是可点击节点列表，尚未绘制道路连线和区域底图。
- NPC 只有确定性的周期迁移，没有完整的有限认知、目标、计划和资源约束。
- 人物互动目前只有通用拜访，身份、门禁、话题、承诺和关系尚未生成上下文菜单。
- 旬结算目前只留下世界日志，尚未改变治安、物价、粮秣、组织和地方机会。
- 场景内容暂时在 C# 工厂中，尚未迁入可审计的外部历史数据和玩法数据文件。
- 存档只有一个本地槽位，尚未提供档位管理、迁移目录和确定性重放。
- 目前没有玩家目标、委托链、职位流转、经营、战斗和阶段性结局。

## 接下来准备做什么

### G1：让行动菜单来自世界状态

1. 增加认识状态、关系维度、身份准入、话题、承诺和人物日程。
2. 定义 `AvailableAction` 查询，由在场人物、地点、身份、关系和已知信息生成中文按钮。
3. 让拜访可能被门禁拒绝、被安排到未来日期，或产生引荐、传闻和承诺。
4. 验收：同一人物在不同身份、关系和地点下显示不同可选行动，不使用硬编码人物专属按钮。

### G2：让旬结算真正改变地方

1. 建立城邑治安、粮价、繁荣、官府控制和道路风险状态。
2. 建立人物的目标、有限认知、计划评估和逐日行动入口。
3. 让玩家旅行、工作和消息行为影响局部变量，旬结算聚合并产生新机会。
4. 验收：静观三旬后至少三座城状态不同；日志能解释变化来自哪些人物、组织或资源压力。

### G3：形成 60 至 90 日个人生涯

1. 给三种身份各自建立谋生渠道、成长路径、准入优势和困境。
2. 加入声望、关系网络、财富压力、承诺和可失败的阶段目标。
3. 加入三个不强制历史结果的局势分支，让玩家可以旁观、利用或介入。
4. 验收：三种身份各可游玩 60 日，拥有不同机会；不行动和积极介入都会产生可解释结果。

### G4：内容工程与历史校核

1. 把地图、人物、道路、城内地点和历史初态迁入版本化数据文件。
2. 每条历史敏感字段记录来源、置信度、争议和玩法假设。
3. 建立交叉引用、重复 ID、路线连通性、日期边界和汉化完整性校验。
4. 验收：场景无需重编译即可扩展，未知史实不会被伪装成精确数字。

## 阶段完成标准

每个阶段必须同时做到：领域规则有自动测试、Release 构建零警告、真实桌面界面走通主路径、计划文档如实更新、提交并推送。新增表现不得越过领域边界直接修改世界状态。
