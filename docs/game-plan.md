- 加入 8 个战略地点、首批城内地点、24 名具名人物和 3 种开局身份。

## 当前真实边界

当前版本是“产品方向纵向切片”，不是功能完备的游戏。

- 地图是可点击节点列表，尚未绘制道路连线和区域底图。
- NPC 已具有目标、有限认知、逐日行动入口、规则化日程和确定性迁移，但当前计划仍是每旬按稳定规则行动一次的最小模型，尚未形成基于资源约束、机会比较与多步承诺的完整计划系统。
- 人物互动已经来自世界状态，但话题传播、引荐网络、恩义偿还和长期关系演化仍是最小实现。
- 旬结算已改变治安、粮价、繁荣、官府控制、道路风险和 0..100 的资源账本；这些人口、粮储、府库和人力数值是由场景地方初态派生的 D 级玩法标定，尚未接入独立历史资源种子。
- 官署、士人网络、商旅和地方守备目前由已审计城内地点稳定生成，并已持有资产、应对地方缺口和发布委托；尚无独立场景审计记录、职位树及组织间关系网络。
- 三种身份已有不同的 60 日生涯路径、财富压力、局势介入方式和资源驱动委托方案，但目前仍是少量模板，尚未形成多层职位树、复杂委托链、经营系统和战斗系统。
- 正式场景已外置并具备来源审计，但首版不少人物记录仍是按通用史传来源归类的 C/D 级材料，尚未为 24 人逐一完成传记主张、具体时点和位置的独立绑定。
- 存档只有一个本地槽位，尚未提供档位管理、迁移目录和确定性重放。
- 已有首个 60 日玩家目标和三条局势结局，但尚未提供复杂委托链、职位流转、经营、战斗和跨阶段生涯结局。

## 接下来准备做什么

### G1：让行动菜单来自世界状态（已完成）

1. 已增加认识状态、好感与信任、身份准入、话题、约见承诺和规则化人物日程。
2. 已定义 `AvailableAction` 查询，由在场人物、地点、身份、关系、日程、已知话题和约见生成中文按钮及受阻原因。
3. 已让初次接触可能被门禁或日程阻止，并可预约未来日期；守约和失约会改变或记录社会状态。
4. 已验收同一人物在不同身份、日期、关系和地点下显示不同可选行动，界面不使用硬编码人物专属按钮。

### G2：让旬结算真正改变地方（已完成）

1. 已建立城邑治安、粮价、繁荣、官府控制和道路风险状态，并在中文界面显示当前地方及可达道路状态。
2. 已建立人物目标、有限认知、人物计划状态和逐日行动入口；当前采用确定性的每旬最小行动计划，便于测试与重放。
3. 已让玩家旅行、谋生和打听消息形成待结算压力，由旬结算与人物行动、地方基础和道路压力共同聚合。
4. 已验收静观三旬后至少三座城形成不同状态；旬报能够区分并解释人物、玩家和资源压力造成的变化。

### G3：形成 60 至 90 日个人生涯（已完成）

1. 已给寒门士子、郡府小吏和游侠分别建立学舍、官署和市集中的身份机会，以及不同成本、能力收益、准入优势和生计困境。
2. 已加入声望、人脉、每旬生活开销、生计压力和可失败的 60 日阶段目标；守约、交游、训练、谋生与身份行动都能留下生涯结果。
3. 已加入京畿流民、东道粮运和颍川征辟三个不强制历史结果的局势分支，玩家可旁观、赶赴当地或按身份介入。
4. 已验收三种身份均可运行完整 60 日并完成不同目标；完全旁观会使目标失败且三条局势自行收束，积极介入会形成另一套可解释结果。

### G4：内容工程与历史校核（已完成）

1. 已把地图、人物、道路、城内地点、身份、话题和地方初态迁入 `189-central-plains.v1.json`，支持显式路径及 `LATEHAN_SCENARIO_PATH` 覆盖。
2. 已为每个敏感实体记录来源、字段覆盖、置信度、争议和玩法假设；没有史料精确支持的能力、坐标、日程和 0..100 初态均标为 D 级。
3. 已建立交叉引用、重复 ID、道路连通性、日期边界、数值范围、来源语义和汉化完整性校验；错误使用稳定的 `SCN-*` 编码。
4. 已验收外部 JSON 改名后无需重编译即可加载；坏引用、重复 ID、断路图、缺少中文、来源遗漏和越界数值均会在创建世界前拒绝。

### G5：让资源、组织与计划形成闭环（进行中）

1. 已为城邑建立人口、粮储、府库和可用人力账本，按旬结算，并明确标为 0..100 的 D 级玩法标定；90 日运行后至少三座城会形成不同资源轨迹。
2. 已让官署、士人网络、商旅和地方守备持有钱财、粮秣、人手与影响；玩家机会由组织需求和资源缺口生成，并具备接受、八日交付期限、完成、失约及十日冷却。职位与组织关系仍待实现。
3. 下一步让 NPC 在目标、有限认知、资源、关系和行程约束下比较机会，形成可取消、可失败、可被玩家打断的多步承诺。
4. 部分验收已完成：90 日资源与组织轨迹分化、玩家结果可沿委托/账本/旬报解释、v5 存档可恢复委托状态。G5 完成前仍需验证 NPC 多步计划与完整确定性重放。

## 阶段完成标准

每个阶段必须同时做到：领域规则有自动测试、Release 构建零警告、真实桌面界面走通主路径、计划文档如实更新、提交并推送。新增表现不得越过领域边界直接修改世界状态。
