# 189 雒阳危机 MVP 行为验收

> 性质：实现无关的可执行规格<br>
> 对应场景：`scenario.189.luoyang_crisis.mvp` 0.1.0<br>
> 对应规则：`latehan.rules.0.1-draft`

## 1. 测试约定

每个用例从原始场景或明确指定的前置存档开始。测试驱动器向模拟核心提交结构化命令；下面的命令行文本只是 CLI 适配器输入样例，不是领域 API。

每次运行保存：

- 规范化命令序列；
- 事件序列及其因果边；
- 玩家可见输出；
- 结束状态哈希和事件日志哈希；
- 场景、规则、随机与引擎版本；
- 性能计数器，但性能数值不进入确定性哈希。

测试不得通过中文显示文本查找领域对象，必须使用稳定 ID。

## 2. 加载与内容错误

### SCN-001 样例原子加载

**当**加载 `manifest.json` 及三个组件，**则**：

- 世界时间为 `0`，玩家位于 `place.luoyang.general_in_chief_office`；
- 所有 ID 唯一，所有引用可解析；
- 所有业务字段受到来源记录覆盖；
- 历史来源 ID 都存在于历史主张库；
- 加载结束前不会调度 NPC 事件；
- 加载成功只产生一个不可进入因果日志的诊断结果，不产生游戏事件。

### SCN-002 悬空地点引用

**给定**副本中把 `person.player_clerk.location` 改为 `place.missing`，**当**加载，**则**加载失败且世界对象为 `null`。诊断包含：

```text
SCN-REF-001
actors.json
$.persons[?id=person.player_clerk].location
place.missing
```

一次运行还应返回其他独立验证错误，不因第一个错误提前退出。

### SCN-003 来源缺失

删除一条路线的 `minutes` 来源覆盖后，验证器必须报告未覆盖字段；把 `historical_claim` 改成不存在的 ID 时，必须报告未知主张。两者都不得退化为警告。

### SCN-004 版本和哈希

- 开发模式允许 `content_hash: pending-tooling`，但必须输出计算值；
- 发布模式拒绝 `pending-tooling`；
- 组件 `scenario_id` 或 `schema_version` 不一致时拒绝加载；
- JSON 键顺序和无意义空白变化不得改变规范化内容哈希。

## 3. 命令与可知边界

### CLI-001 初始观察不泄密

执行：

```text
look
status
commitments
```

游戏时间保持为 `0`。输出可以显示李文、府中活动、玩家持有的封记、凭记和两项约定；不得显示：

- 张让的计划、位置或威胁置信度；
- 董卓的客观位置；
- 文书封内命题，除非玩家已经拆封；
- `objective_status`、NPC 属性数值、随机种子或事件队列。

### CLI-002 无效与歧义命令不耗时

以下输入返回结构化错误且时间仍为 `0`：

```text
go nowhere
give sealed_note
talk 张
```

错误分别表示地点未知、缺少接收人、别名歧义或不存在；不得偷偷选择第一个匹配项。

### CLI-003 不可能行动说明直接障碍

玩家在大将军府执行 `enter place.luoyang.changle_palace`，因目标并不相邻而返回 `blocked:not_adjacent`，不推进时间。玩家到达北宫后尝试进入长乐宫，访问行动可以消耗通报时间后得到 `refused:explicit_palace_escort_required`。

第二种结果只能说明门禁拒绝；不能泄露张让是否在内、太后当前计划或潜在危险。

### CLI-004 开发者查询不污染角色

运行 `dev what-knows person.zhang_rang` 后保存、继续五分钟，再与未运行开发者命令的分支比较。两个分支的事件日志、世界状态、随机游标和玩家信念哈希必须一致。

## 4. 行动、时间和部分结果

### ACT-001 按时交付并回报

从开局执行一条有效最短路径：

```text
go place.luoyang.sili_office walk
give item.sealed_note_to_yuan_shao to person.yuan_shao
go place.luoyang.general_in_chief_office walk
tell person.li_wen proposition.general_office_requests_status
```

验收不绑定具体叙事措辞，但必须产生以下因果结构：

```text
travel_started -> travel_completed
travel_completed + item_held -> item_transferred
item_transferred -> commitment.player.deliver_note completed
return_travel_completed + player_report -> commitment.player.report_back completed
```

封记只存在一个持有者；交付和回报分别完成两个承诺；所有时间和行动成本非负且总耗时等于各阶段事件之和。

### ACT-002 拆封后仍可交付，但不是完整成功

执行 `read item.sealed_note_to_yuan_shao`，确认拆封，再交给袁绍。结果必须至少包含：

- 封印状态变化和玩家获得命题认知；
- 李文可在回报或后续检查中发现封印破坏；
- 物品仍能被实际转移，不把“失信”误作物理交付失败；
- 交付承诺可标为 `completed_with_breach` 或等价的两项事件；
- 关系/纪律后果引用拆封事件，而不是无来源扣数值。

### ACT-003 途中事件造成部分完成

使用固定测试随机流令骑马阶段在已行进 40 分钟后发生马伤：

- 40 分钟和已消耗马料保留；
- 玩家、马和文书停在同一路段状态，不瞬移回起点；
- 行动状态为 `interrupted`，允许改步行、等待、求助或取消；
- 取消后产生 `partially_completed` 和失约风险，已发生事件不删除。

### ACT-004 到达后拒收

令袁绍在玩家到达前离署，并由门吏拒绝代收。旅行和等待照常发生，物品仍由玩家持有，交付承诺仍开放。结果为一组事件，不是将整条命令回滚为 `false`。

### TIME-001 同刻控制变化先于交付

在分钟 `180` 同时排定：

- 宫门控制规则收紧；
- 一名信使到达并试图交付依赖旧权限的文书。

按优先级先应用 `access_and_control_change`，再应用 `arrival_and_departure` 与 `delivery_and_transfer`。交付被新权限阻止。重复运行 100 次以及改变容器插入顺序，事件与状态哈希必须相同。

### TIME-002 等待被重要中断截断

玩家执行 `wait 4h`，第 95 分钟出现直接面向玩家的紧急召回。时间停在 95，等待行动标记为 `interrupted`，其余 145 分钟尚未发生。非玩家相关的远方普通事件只进入摘要，不应无故打断。

## 5. 认知、传言和计划

### KNOW-001 假城门消息不会改变客观城门

玩家从市场人群听到 `proposition.north_gate_closed` 并复述给孙和：

- 两人各自产生带来源、时间和置信度的信念；
- 北门 `open` 状态不因信念改变；
- 陈直的反向直接观察不会自动广播给全城；
- 玩家亲自到北门观察后更新自身信念，但孙和只有在收到新消息后才更新。

### KNOW-002 同一消息在传播中保留谱系

群体传言升格出一名具名商旅并向玩家复述时，新消息事件引用群体传言事件；具名人物从 `group.market_population` 原子减一生成，不增加总人数。复述可以改变文本版本或置信度，但不得丢掉上游来源链。

### PLAN-001 错失承诺可解释

玩家开局步行前往成皋方向，导致两个承诺过期。系统必须分别记录：

- 交付未发生：玩家携文书离开可达袁绍的路线，且期限到达；
- 回报未发生：交付结果尚未形成且玩家不在李文可接触范围；
- 李文只有通过观察玩家缺席、检查文书状态或收到消息后才能知道失约，不能在期限瞬间全知。

### PLAN-002 NPC 计划会取消或改道

向张让送达可信、可核验的安全离宫安排，并把威胁信念降至取消阈值以下。`plan.zhang_rang.secure_survival` 必须取消或替换，取消事件引用消息和信念变化。不得因为历史基线需要宫变而恢复原计划。

### PLAN-003 无消息送达就无同步反应

截断成皋报状的载体后，何进不能在报状原定到达时获得 `proposition.qiao_mao_holds_chenggao`。桥瑁状态可以继续变化，但雒阳人物只依据旧消息决策。

## 6. 历史约束与非脚本基线

### HIST-001 官职和控制边界

场景与运行时始终满足：

- 王允是河南尹，但不因此直接控制宫门守卫；
- 袁绍是司隶校尉，其授权不等于任意进入宫中；
- 桥瑁是东郡太守并暂屯成皋，不是成皋本地长官；
- 八月开局不得把张邈初始化为陈留太守；
- 董卓的开场位置保持范围精度，除非运行中移动或新证据使其具体化；
- 丁卯日道路风险可受长期降雨影响，但天气系统不得把史料主张解释为雒阳必然正在下雨。

### HIST-002 历史基线来自规则

固定场景和根种子，无玩家干预推进至分钟 `6060`。允许得到与史实相近或偏离的结果，但检查：

- 没有按历史日期直接写入“何进死亡”“皇帝出逃”或“董卓接驾”的定时事件；
- 每个重大结果都能从计划、消息、行动、门禁和状态变化追溯；
- 删除或延误一个必要条件后，相关结果可以不发生；
- 运行不会因历史事件未发生而崩溃或强制纠偏。

实现第一次稳定基线后，将事件日志哈希登记为该规则小版本的黄金样本。规则或场景内容变化时只能通过审核更新，不能在测试中模糊匹配旧结果。

### HIST-003 分叉具有局部而非魔法式影响

在分钟 `0` 从同一状态分三线：

| 分支 | 玩家行为 |
|---|---|
| A | 等待 6 小时 |
| B | 按时交付封记并回报 |
| C | 向市场和孙和传播北门关闭假消息 |

到分钟 `360` 比较。B 应直接改变袁绍获知状态与李文的承诺判断；C 应改变传言谱系、部分旅行选择和可能的城门排队。任何分支都不得仅因一次低阶行为直接改写董卓性格、凭空关闭城门或修改远方库存。所有差异必须有跨分支的首个分歧事件。

## 7. 存档、回放和迁移

### SAVE-001 运行中行动存档

在一次分阶段旅行的中断点保存，加载后继续。比较不中断原运行：

- 已付时间、马料和行动阶段一致；
- 下一个排定事件一致；
- 随机流游标一致；
- 最终世界状态和事件日志哈希一致。

### SAVE-002 快照加事件回放

从分钟 `0` 全量重放和从分钟 `180` 快照继续至 `6060`，最终状态哈希一致。快照不是权威历史，损坏快照可由之前快照和事件恢复。

### SAVE-003 不兼容版本拒绝

将存档 `ruleset_version` 改成未知主版本。加载器必须拒绝继续模拟，列出需要的规则版本和可用迁移器；不得静默采用当前规则。迁移只能生成新存档并保留原文件。

## 8. 世界不变量

每个行为用例结束后统一检查：

1. 人物和物品最多处于一个具体位置/持有关系；旅行中使用显式路段状态。
2. 钱、口粮、马料和可转移物品的变化有产生、转移、消费或损耗事件。
3. 死亡、被移除或被拘禁且无授权行动的人物不产生普通计划行动。
4. 人物信念变化必须有感知、推理、遗忘或调试干预来源。
5. 事件原因只能引用更早事件或同批次允许的已排序事件，不形成因果环。
6. 计划到期、取消和错失都有终结状态，不永久留在活动队列。
7. LOD 升降不改变总人数、总资源、稳定身份或已形成承诺。
8. 玩家与 NPC 使用同一移动、交付、访问和消息规则。
